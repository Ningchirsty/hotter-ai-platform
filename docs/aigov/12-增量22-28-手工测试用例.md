## 一、使用方法与判定总则

1. **执行顺序**：`TC-ENV`（环境）→ `TC-TOK`（服务令牌，风险最高）→ `TC-SBX`（沙箱产物）→ 其余组。
   `TC-SEC` 是负向总检，可随时穿插。
2. **每条用例三件事**：操作步骤、**预期结果**、**证据**。证据优先取**数据库行 / 响应头 / 响应体原文**，
   不要只写"正常"。
3. **结果栏**：`☐通过 ☐失败` + 备注（失败时写实际值与脱敏后的原始响应）。
4. **不符即报缺陷**：预期里凡是写"**拒绝**"的，都要求**能看出拒绝的原因**（消息点名了字段/门槛），
   且**拒绝路径不留半成品**（不写库、不落对象存储）。若出现"拒绝了但数据已经变了"，
   **按高危上报**——那是 fail-closed 被破坏。
5. **只读优先**：能只读验证的不要写数据；写了数据的用例，步骤里都给了"清理"。

**判定用到的三个通识**

- 未登录访问任何 `/aigov/**` → **401**；已登录但无权限 → **403**；路径写错 → **404**。
  把 401 当 404 会误判"端点没上线"。
- 接口返回统一包 `{code, msg, data}`；`code=200` 才是成功。
- 响应头大小写不敏感。

| 入口 | 为什么可以不防重 |
|---|---|
| `AigTaskCallbackController#receive` | 自带签名 + `(providerCode,eventId)` 幂等键；加防重反而会吞掉"重复投递"这条需要被记录的信号 |

| `AigStudioDraftController#update` | 内容哈希守卫：内容没变就不产生新修订 |
| `AigStudioDraftController#rollback` / `#archive` | 目标态幂等（回滚到指定修订号 / 归档是终态收敛） |
| `AigUserBrandController#revoke` | 软停用（不物理删、可重新登记恢复），重复执行同一终止态 |
| `AigInvokeController#dryRun`、`AigModelController#testConnection`、`#runHealthProbe` | 预演 / 探测，无副作用 |
| `AigStudioDraftController#validate`、`AigRolePackageController#validate`、`#validateStored`、`AigPortalController#suggest` | 只读式校验/建议，不写库 |
| `AigPortalController#refreshMyAssets` | 幂等重建当前用户资产索引 |

★★**一条必须知道的运行时语义（读 `RepeatSubmitAspect` 得来）**：防重键**只在第一次请求
`code=200` 时保留**；第一次失败会被 `AfterReturning` 删键、抛异常会被 `AfterThrowing` 删键

那个测法本身是错的（我原本就打算这么测）。该注解防的是"**成功之后**又被点一次"，
而那恰好是会造成重复账本 / 重复计费 / 重复推进的那种。
