# 12 增量 22–28 手工测试用例（操作类）

> **用途**：给测试人员在生产（或与生产同构的环境）上逐条执行、留证。
> **配套文档**：`11-新增表与菜单-生产执行单.md` 负责"把东西装上"（建表、种菜单、发镜像）；
> 本文负责"装上以后对不对"。**先跑完 11 的 §三～§六，再开始本文的 TC-ENV 组。**
>
> **预期一律来自代码**（权限串、拒绝文案、字段校验都是从源码里抄出来的，不是推测）；
> 若实际结果与"预期"不符，按 §一.4 处理，不要自行改成"也合理"。

## 一、使用方法与判定总则

1. **执行顺序**：`TC-ENV`（环境）→ `TC-TOK`（服务令牌，风险最高）→ `TC-SBX`（沙箱产物）→ 其余组。
   `TC-SEC` 是负向总检，可随时穿插。
2. **每条用例三件事**：操作步骤、**预期结果**、**证据**。证据优先取**数据库行 / 响应头 / 响应体原文**，
   不要只写"正常"。
3. **结果栏**：`☐通过 ☐失败` + 备注（失败时写实际值与脱敏后的原始响应）。
4. **不符即报缺陷**：预期里凡是写"**拒绝**"的，都要求**能看出拒绝的原因**（消息点名了字段/门槛），
   且**拒绝路径不留半成品**（不写库、不落对象存储）。若出现"拒绝了但数据已经变了"，
   **按高危上报**——那是 fail-closed 被破坏。
5. **只读优先**：能只读验证的不要写数据；写了数据的用例，步骤里都给了"清理"。

**判定用到的三个通识**

- 未登录访问任何 `/aigov/**` → **401**；已登录但无权限 → **403**；路径写错 → **404**。
  把 401 当 404 会误判"端点没上线"。
- 接口返回统一包 `{code, msg, data}`；`code=200` 才是成功。
- 响应头大小写不敏感。

### 2.4 数据前置（一次准备，多组复用）

1. **对象存储已配置**：`sys_oss_config` 里至少一条 `status` 启用的配置。
   没有的话产物上传会报 `产物字节留存失败（对象存储不可用或未配置）…请确认 sys_oss_config 有启用中的配置`。
2. **一个可推进的 Agent 版本**（`aig_agent_version`，状态 `VALIDATED` 或更早），用于沙箱与门槛用例。
3. **一个训练草稿**：`aig_admin` 登录 `/ai-gov/studio` → 新建草稿（`agentCode` 必填，
   `contentJson` 留空时服务端会填骨架），记下 `draftId` 与**当前修订号**（后续 CAS 用例要用）。
4. **一段可用的沙箱作业产物**。若宿主侧不便真跑，可用下面这份**最小 `result.json`** 先验证平台侧
   （注意：这样就验不到"结果来自真实执行"，只能验平台校验逻辑；真跑作业见 TC-SBX-19）：
   ```json
   {
     "jobId": "job-mt-001",
     "image": "hotter-sandbox-example:1.0",
     "exitCode": 0,
     "timedOut": false,
     "network": "none",
     "artifacts": [
       { "path": "out/report.json", "bytes": 20, "sha256": "<对 out/report.json 真实内容实算的 64 位小写摘要>" },
       { "path": "out/log.txt",    "bytes": 11, "sha256": "<同上>" }
     ]
   }
   ```
   > `path/bytes/sha256` **必须与你要上传的文件逐字节对应**——这三个值是后面所有上传校验的基准。
   > 摘要算法：`sha256sum out/report.json`。
