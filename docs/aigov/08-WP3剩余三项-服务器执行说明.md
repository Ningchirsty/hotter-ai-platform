⚠️ **看响应体的 `code`，不要看 HTTP 状态码**——RuoYi 的 HTTP 状态码恒为 200（见 07 附录 A.9.1）：

| 请求 | 响应体 `code` | 含义 |
|---|---|---|
| `GET /aigov/agent/list`（无 token） | 401 或 403 | 路由已注册、鉴权生效（若是 404 → 后端还是旧包） |
| `GET /aigov/agent/not-exists` | **404** | 路径变量带数字约束，拼错就是 404（不是 400） |
| `POST /aigov/agent/release/advance` 传**合法但过时**的 `expectedStatus`（版本实际已是 `STABLE`，却传 `DRAFT`） | 报「**你的视图已过期**：库中当前状态是 STABLE…」 | 服务层的「视图过期」判据生效 |
| 同上，但传**非法**状态值（如 `BOGUS`） | 报「**未知的当前状态：BOGUS**」 | 在**解析阶段**就被拒，**到不了**「视图过期」那句 |

> ⚠️ **这两句不是同一句话，别照字面找错。** 早期文档把「传错误 `expectedStatus`」等同于「视图已过期」，
> 但实测：非法枚举值走的是解析分支，只有**合法但已过时**的状态才会命中「视图已过期」。
> 要验「视图过期」判据，必须传一个合法状态值。

### 2.1 新增接口与权限点

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /aigov/agent/package/upload` | `aig:package:upload` | multipart：`file`（包体）+ `manifestJson`（表单字段）+ `sourceRef`；**要求携包体** |
| `POST /aigov/agent/package/version/{id}/install` | `aig:package:install` | 按 Manifest 声明建出 Agent/Skill 版本（均为 DRAFT） |
| `GET /aigov/agent/package/version/{id}/install-log` | `aig:package:query` | 追加型安装账本 |

> ⚠️ **三个响应字段名：照直觉猜会猜错（都实测过，2026-10-08）**
> 1. `POST /package/version/{id}/scan` 返回的是 `AigManifestScanResult`，它**没有 `scanResult` 字段**
>    （`scanResult()` 是普通方法、不是 Lombok getter，**不参与序列化**）——判据要读 **`pass`**（`true` = PASS）。
>    `scanResult` 这个名字只出现在**上传响应**（`AigPackageRegisterVo`）与**库里的列**（`scan_result`）；
> 2. 安装结果里表示「本次是否为重复调用」的字段叫 **`alreadyInstalled`**（不是 `idempotent`）；
> 3. 安装项里指向父对象的字段叫 **`parentId`**（不是 `objectId`），版本字段是 `versionId`、是否本次新建是 `created`。
>
> 另外：平台把 **Long 序列化成 JSON 字符串**（防 JS 精度丢失），
> 因此 `packageId` / `packageVersionId` / `userId` 这类值**不要与数字直接比较**
> （`"2107…" != 2107…`）——第一版校验脚本就因此误报过一次 FAIL。

新增权限点已种进 `aig_agent_registry_menu.sql`（授权只给 `aig_admin`：两者都是写动作）。
**忘了种就会被 `AigPermissionSeedCoverageTest` 在构建期拦下**（这条测试在本轮真的拦到过一次）。

### 2.2 两处落库口径（你让我定的两条，已定）

| 字段 | 决定 | 理由 |
|---|---|---|
| `data_level` | **进 `config_json`，不加列** | 目前没有任何代码按「Agent 版本的数据等级」拦截（生效的是模型路由层的数据等级）；此时加列只是多一处"存了但没人读"，等要做「按版本限制可处理的数据等级」时再提升为列 |
| `scenario_codes` | **进 `config_json`；恰好声明一个时同时写版本的 `scenario_code` 列** | 该列是单值：一个场景落列（既有的按场景过滤/路由认得它），多个只进 config_json，**不擅自挑一个** |
| 其余无列字段（`min_platform_version`/`dependencies`/`roles`/`network_access`/`network_hosts`/`upgrade_policy`/`rollback_policy`） | 进 `config_json`，原样保留 | 不能默默丢掉 |
| `knowledge_scope` | 写 **`knowledge_scope_json` 列**（有列） | — |

另外两处语义选择：
- **要求携包体**：服务端据此算 SHA-256 并与 Manifest 声明的 `checksum` 比对，校验和从此不是调用方说了算；
  不一致整笔拒绝、不落库。**包体本身不入库**（声明式 Package 的安装只读 Manifest），
  要留存包体应交给平台文件服务并把键填进 `sourceRef`；
- **`aig_package.checksum` 随每次上传更新为「最近一次包体哈希」**：冻结首次会让第二个版本
  被自己的交叉核对（Manifest 声明 vs 包记录）误判为「校验和不一致」。

### 2.3 安装的守门与幂等

1. 包/版本必须存在、包未停用；
2. **`scan_result` 必须是 PASS**（查库里的证据，不是调用方声明）——被拒的版本仍可登记留痕（`REJECT`）但不能安装；
3. Manifest 必须声明了内容物（`agents`/`skills` 非空），否则报「没有内容可安装」；
4. **幂等**：以「已存在指向该 Package 版本的 Agent/Skill 版本行」为判据（日志是审计，不是状态），
   重复调用不重复建行；
5. 装出来的版本一律 **DRAFT**：安装不等于发布，发布门槛照旧要逐道过。

### 2.4 Manifest 新增的内容物声明

```json
"skills": [{"code":"image-fitter","name":"图像适配","capabilities":["image_generation"],"allow_external":"N"}],
"agents": [{"code":"vision-planner","name":"视觉规划","category":"PLANNING","golden_cases":["case-a"]}]
```
子字段同样白名单（未声明字段即拒），必填：skill 的 `code/name`、agent 的 `code/name/category`；
`category` 必须是已知类别，`allow_external` 只能 Y/N，同一清单编码不得重复；
**与 `package_type` 必须一致**（AGENT 包不能带 skills、SKILL 不能带 agents、MIXED 两者都要有）。
不声明内容物仍能通过 Manifest 校验（校验管的是拒绝规则），但安装会明确报出来。

### 2.5 停用与包体留存（第二期已补，2026-10-08）

**停用入口已实现**：`POST /aigov/agent/package/version/{id}/disable`（权限 `aig:package:disable`，
只给 `aig_admin`）。停用对象＝**回指该 Package 版本的版本行**（与安装的幂等判据同源），
同一个 Agent 的其它版本一律不动；状态迁移走发布状态的**唯一写入口**（`advanceRelease`），
因此每个版本都会按状态机判定边、CAS 更新、并留一条发布事件；账本写一行 `DISABLE/PASS`。
已在停用状态的按幂等处理（不改库、不写账本）；已归档的跳过并给出原因；
**一条也停不了**或**从没装过**都明确报错（不记一条没做任何事的账）。

**包体留存已实现（默认关闭）**：开关 `aigov.package.store-body`，默认 `false`（与升级前行为完全一致）。
开启后包体留存在对象存储、对象键写在该**版本**的 `body_ref` 列（逐版本，不是逐包——每次上传的包体

`bodyStored`/`bodyRef` 都会如实回报；开启后留存失败即整笔上传失败（不落半截状态）。
存量库需要跑迁移 `script/sql/aig_package_version_body_ref.sql`（幂等）。
⚠️ 开启前确认 `sys_oss_config` 有启用中的配置，否则上传会从"能用"变成"报错"。

**包级停用/启用也已实现**：`POST /aigov/agent/package/{id}/disable` 与 `/enable`（同一权限点
`aig:package:disable`）。包级停用后**不再接受新版本上传、不能安装**，但**不动**已经装出去、
正在被使用的版本——要下线那些版本走版本级「停用」。两个方向都可逆、都幂等。

仍未做：`aig_package.source_ref` 与对象存储的联动（包体留存已由 `aigov.package.store-body` 管，

### 3.2 菜单怎么补（**已种，见 `script/sql/aig_agent_registry_pages.sql`**）

权限行（`menu_type='F'`）在 `aig_agent_registry_menu.sql`；页面菜单（`menu_type='C'`）单独一份
`aig_agent_registry_pages.sql`——分成两份的**原因**是权限行当初就必须先种（后端先上线），
而页面菜单得等页面存在（种早了用户点进去是 404）。两份都可重放。

页面菜单：5 行，父级 `AI平台治理`（`1763000000000000001`），权限用各自的 list 权限
（沿用 RuoYi 约定：页面用列表权限，按钮级权限是独立行）。授权：三个角色都给页面（读语义）。

⚠️ **两个容易漏的坑（都已在脚本里处理）**：

1. **父菜单也必须授权**：只授权子页面、不给父菜单授权时，**菜单树里根本看不到这个页面**
   （RuoYi 按"用户已授权的菜单"建树，父节点不在集合里，子节点就没有挂载点）。
   脚本因此显式补了一次父菜单授权（幂等）。
2. **页面菜单的守卫不能带 perms 条件**：`aig_agent_registry_menu.sql` 的守卫是
   「menu_id 不存在 **且** 该 perms 不存在」，用来避免同权限种两遍；页面的 perms 故意与列表权限行
   重名，带上 perms 守卫会让页面菜单**永远插不进去**。所以 pages 脚本只按 menu_id 判断。
   另外同一个 list 权限被多个页面共用是允许的（如 Agent 页面与绑定页面都用 `aig:agent:list`）。

写法沿用：显式列名 + `insert ... select ... where not exists` / `insert ignore`（可重放），

**步骤**：目标库跑完脚本 → 配好 datasource 与 redis → 设好 `HR_ENCRYPT_KEY` → 启动后端 → 观察日志。

**通过判据**（逐条）：

1. 日志出现 `Started ...Application in ... seconds`，且**没有** `APPLICATION FAILED TO START`；
2. `GET /aigov/agent/list`（不带 token）响应体 **`code=401`**，不是 404
   —— 说明 WP3 的 Controller 真的注册上了；
3. `GET /aigov/agent/not-exists` 响应体 **`code=404`**；
4. 登录后 `GET /aigov/agent/list` 返回 `code=200`，且能看到 4 个内置 Agent；
5. `GET /aigov/evaluation/case/list` 返回 `code=200` 且 8 条用例。

⚠️ **三个姿势问题**（不搞清楚会把"正常"误判成"失败"，详见 A.9.1）：

- **HTTP 状态码恒为 200** —— 判据看响应体的 `code`，不要看 HTTP 状态码；
- **缺 `HR_ENCRYPT_KEY` 起不来** —— 这是 fail-closed 的设计（宁可不启动也不静默存明文）；
- **登录接口带 `@ApiEncrypt`** —— `api-decrypt.enabled=true` 时明文登录被 403 挡住，
  命令行烟测要么按协议加密、要么临时 `--api-decrypt.enabled=false`；带 token 的请求
  除 `Authorization` 外还要 `clientid` 头。

**启动失败时先看什么**（按最可能顺序）：

- `mybatis-encryptor.password 不能为空` → **没设 `HR_ENCRYPT_KEY`**（A.9.1 第 2 条）；
- `BeanCreationException` / `NoSuchBeanDefinition` → 某个 WP3 服务没被扫描到（包路径是否在组件扫描范围内）；
- `ApplicationContextException: Ambiguous mapping` → 路由冲突（已确认各控制器前缀互不重叠）；
- `MyBatisSystemException` / mapper 相关 → Mapper 扫描或 `@Select` 解析问题；
- 中文乱码或 1366 → **目标库不是 utf8mb4**（见 07 附录 A.3）。
