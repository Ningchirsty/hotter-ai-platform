## 二、待办一：Package 上传与安装链路

### 2.1 现状 / 缺口

**已有**：`aig_package`、`aig_package_version`（含 `manifest_json` / `manifest_hash` / `scan_result` / `scan_detail` /
`release_status` / `sandbox_project_id` / `evaluation_run_id` / `rollback_target_version_id`）、
`aig_package_install_log`（追加型账本）、`AigPackageManifestValidator`（§6.2 五类拒绝规则）、
`POST /aigov/agent/package/version/{id}/scan`、Package/版本的只读接口。

**缺**：上传（包体存哪）、**建包与版本的写入口**、**安装**（Package → Agent/Skill + 版本行）、
`aig_package_install_log` 的写入方、以及上传/安装的权限点。

### 2.2 建议的落地顺序（每步都可单独验收）

1. **上传**：包体放对象存储（建议键 `packages/<package_code>/<version>/<file>`），返回 `source_ref`；
   服务端算包体 SHA-256 作为 `aig_package.checksum`。**限制大小与类型**，并记录上传人。
2. **建包与版本**（新写接口，例如 `POST /aigov/agent/package`）：
   入参 = 包身份 + `version` + `manifest_json` 原文；
   服务端**先算 `manifest_hash`（对原样字节）**→ 写 `aig_package`（不存在则建）→ 写 `aig_package_version`
   （`release_status='DRAFT'`、`scan_result=null`）。
   重复 `(package_id, version)` 由唯一键挡住，报「版本已存在」——**版本不可变，不允许覆盖**。
3. **扫描**：复用现有接口（权限 `aig:package:scan`）。结论=`REJECT` 时版本可保留但不能推进
   （`MANIFEST_VALIDATION` 门槛会查 `scan_result`，见附录 A.4）。
4. **安装**（`scan_result='PASS'` 且人工批准之后）：按 `package_type`（AGENT/SKILL/MIXED）
   创建/复用 `aig_agent` / `aig_skill` 及其版本，写 `config_json` 映射，版本的 `package_version_id` 回指；
   **每个动作写一行 `aig_package_install_log`**（追加型，不更新不删除）。
   安装出来的版本 `release_status='DRAFT'`——**安装不等于发布，不跳门槛**。
5. **幂等**：以「该 `package_version_id` 是否已安装」为判据（查一次 install_log），重复调用不重复建版本。
6. **失败/卸载处置**：把该包带进来的 Agent/Skill 版本置 `DISABLED`（走 `advanceRelease` 的运维边，
   会记发布事件），并写 install_log。

### 2.3 Manifest → 落库映射（含三处**没有对应列**的地方）

| Manifest 字段 | 落点 |
|---|---|
| `package_code` / `name` / `package_type` / `publisher` / `license` / `checksum` | `aig_package` 同名列 |
| `version` / 原文 / 原文哈希 | `aig_package_version.version` / `manifest_json` / `manifest_hash` |
| `prompt_template` | `aig_agent_version.prompt_template` |
| `input_schema` / `output_schema` | 同名同名列 |
| `required_tools` / `forbidden_tools` | `allowed_tools` / `forbidden_tools`（首期 `required_tools` 必须为空） |
| `golden_cases` | **`config_json.golden_cases`**（评测从这里读，见第七步；Package 版本的用例集合就来自 Manifest） |
| `data_level` | ⚠️ **Agent/Skill 版本表没有这一列** → 进 `config_json`（若要做成硬约束，需要加列，另评） |
| `scenario_codes` | Agent 版本只有 `scenario_code`（单值）→ 要么要求只声明一个，要么进 `config_json` |
| `min_platform_version` / `dependencies` / `roles` / `network_access` / `network_hosts` / `upgrade_policy` / `rollback_policy` | ⚠️ 都没有对应列 → 进 `config_json`；`rollback_policy` 若要可执行可另写 `rollback_target_version_id` |

> 这三处「没有对应列」是**刻意的现状**（表是按 §5.3 的列设计的），安装时要显式决定写进
> `config_json` 还是加列——不要默默丢掉，那会让「Manifest 声明了但平台没落库」无法追溯。

### 2.4 需要补的权限点

上传与安装会改数据，应各占一个权限点（例如 `aig:package:upload`、`aig:package:install`）。
**必须同时加进** `AigConstants` **与** `script/sql/aig_agent_registry_menu.sql`，
否则 `AigPermissionSeedCoverageTest` 会在构建期直接红——这条测试就是为「新增权限忘了种菜单 →
接口对所有人 403」准备的。

### 2.5 完成判据

一个第三方视觉规划 Skill 能走完：**上传 → 建包（DRAFT）→ 扫描 PASS → 安装出 Agent/Skill 版本（DRAFT）
→ 评测（用例集合来自 Manifest 的 `golden_cases`）→ 三方审批 → Candidate → 灰度 → Stable → 停用/回退**，
且每一步在 `aig_package_install_log` 与 `aig_release_event` 里留痕、重复调用幂等。

### 3.2 菜单怎么补（**14 个权限行已经在库里，页面菜单还没种**）

现在只种了权限行（`menu_type='F'`），因为页面还不存在——种了页面点进去就是 404。
页面做好后，给每个页面补一行 `menu_type='C'`，父级指向 `AI平台治理`（`1763000000000000001`），
权限用对应的 list 权限（父菜单本身不带按钮级权限也可以，但**角色必须能看见父菜单**）。

⚠️ **一个容易漏的坑**：只授权按钮行、不给父菜单授权时，**菜单树里看不到这个页面**
（RuoYi 按"用户已授权的菜单"建树，父菜单不在集合里，子节点就没有挂载点）。
所以补页面菜单时要**同时**给 `sys_role_menu` 补父菜单授权（`aig_admin` / `aig_security` / `aig_viewer`
按各自的只读/可写范围）。新增菜单与授权建议照 `script/sql/aig_agent_registry_menu.sql` 的写法：
显式列名 + `insert ... select ... where not exists`（可重放），不要用纯 `insert`
（`aig_ai_gov_menu.sql` 重放会在第一条 `ERROR 1062`）。

## 四、待办三：整机启动烟测

对应 `07` 手册 **附录 A.5 第 3 条**——这是本地唯一没做的一项（本地只做了离线的上下文装配与路由表检查）。

**步骤**：目标库跑完脚本 → 配好 datasource 与 redis → 启动后端 → 观察日志。

**通过判据**（逐条）：

1. 日志出现 `Started ...Application in ... seconds`，且**没有** `APPLICATION FAILED TO START`；
2. `GET /aigov/agent/list`（不带 token）返回 **401/403**，不是 404 —— 说明 WP3 的 Controller 真的注册上了；
3. `GET /aigov/agent/not-exists` 返回 **404**；
4. 用 `aig_admin` 登录后 `GET /aigov/agent/list` 返回 200，且能看到 4 个内置 Agent；
5. `GET /aigov/evaluation/case/list` 返回 7 条用例。

**启动失败时先看什么**（按最可能顺序）：

- `BeanCreationException` / `NoSuchBeanDefinition` → 某个 WP3 服务没被扫描到（包路径是否在组件扫描范围内）；
- `ApplicationContextException: Ambiguous mapping` → 路由冲突（本次已确认 9 个控制器前缀互不重叠）；
- `MyBatisSystemException` / mapper 相关 → Mapper 扫描或 `@Select` 解析问题（本地探针已用真 SqlSessionFactory 验过 8 张表）；
- 中文乱码或 1366 → **目标库不是 utf8mb4**（见附录 A.3）。
