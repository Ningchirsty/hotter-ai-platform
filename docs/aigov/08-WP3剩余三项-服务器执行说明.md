### 2.1 新增接口与权限点

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /aigov/agent/package/upload` | `aig:package:upload` | multipart：`file`（包体）+ `manifestJson`（表单字段）+ `sourceRef`；**要求携包体** |

**忘了种就会被 `AigPermissionSeedCoverageTest` 在构建期拦下**（这条测试在本轮真的拦到过一次）。

### 2.2 两处落库口径（你让我定的两条，已定）

| 字段 | 决定 | 理由 |
|---|---|---|
| `data_level` | **进 `config_json`，不加列** | 目前没有任何代码按「Agent 版本的数据等级」拦截（生效的是模型路由层的数据等级）；此时加列只是多一处"存了但没人读"，等要做「按版本限制可处理的数据等级」时再提升为列 |
| `scenario_codes` | **进 `config_json`；恰好声明一个时同时写版本的 `scenario_code` 列** | 该列是单值：一个场景落列（既有的按场景过滤/路由认得它），多个只进 config_json，**不擅自挑一个** |
| 其余无列字段（`min_platform_version`/`dependencies`/`roles`/`network_access`/`network_hosts`/`upgrade_policy`/`rollback_policy`） | 进 `config_json`，原样保留 | 不能默默丢掉 |
| `knowledge_scope` | 写 **`knowledge_scope_json` 列**（有列） | — |

另外两处语义选择：
- **要求携包体**：服务端据此算 SHA-256 并与 Manifest 声明的 `checksum` 比对，校验和从此不是调用方说了算；
  不一致整笔拒绝、不落库。**包体本身不入库**（声明式 Package 的安装只读 Manifest），
  要留存包体应交给平台文件服务并把键填进 `sourceRef`；
- **`aig_package.checksum` 随每次上传更新为「最近一次包体哈希」**：冻结首次会让第二个版本
  被自己的交叉核对（Manifest 声明 vs 包记录）误判为「校验和不一致」。

### 2.3 安装的守门与幂等

1. 包/版本必须存在、包未停用；
2. **`scan_result` 必须是 PASS**（查库里的证据，不是调用方声明）——被拒的版本仍可登记留痕（`REJECT`）但不能安装；
3. Manifest 必须声明了内容物（`agents`/`skills` 非空），否则报「没有内容可安装」；
4. **幂等**：以「已存在指向该 Package 版本的 Agent/Skill 版本行」为判据（日志是审计，不是状态），
   重复调用不重复建行；
5. 装出来的版本一律 **DRAFT**：安装不等于发布，发布门槛照旧要逐道过。

### 2.4 Manifest 新增的内容物声明

```json
"skills": [{"code":"image-fitter","name":"图像适配","capabilities":["image_generation"],"allow_external":"N"}],
"agents": [{"code":"vision-planner","name":"视觉规划","category":"PLANNING","golden_cases":["case-a"]}]
```
子字段同样白名单（未声明字段即拒），必填：skill 的 `code/name`、agent 的 `code/name/category`；
`category` 必须是已知类别，`allow_external` 只能 Y/N，同一清单编码不得重复；
**与 `package_type` 必须一致**（AGENT 包不能带 skills、SKILL 不能带 agents、MIXED 两者都要有）。
不声明内容物仍能通过 Manifest 校验（校验管的是拒绝规则），但安装会明确报出来。

### 3.2 菜单怎么补（**16 个权限行已经在库里，页面菜单还没种**）

现在只种了权限行（`menu_type='F'`），因为页面还不存在——种了页面点进去就是 404。
页面做好后，给每个页面补一行 `menu_type='C'`，父级指向 `AI平台治理`（`1763000000000000001`），

## 四、待办三：整机启动烟测

对应 `07` 手册 **附录 A.5 第 3 条**——这是本地唯一没做的一项（本地只做了离线的上下文装配与路由表检查）。

**步骤**：目标库跑完脚本 → 配好 datasource 与 redis → 启动后端 → 观察日志。

**通过判据**（逐条）：

1. 日志出现 `Started ...Application in ... seconds`，且**没有** `APPLICATION FAILED TO START`；
2. `GET /aigov/agent/list`（不带 token）返回 **401/403**，不是 404 —— 说明 WP3 的 Controller 真的注册上了；
3. `GET /aigov/agent/not-exists` 返回 **404**；
4. 用 `aig_admin` 登录后 `GET /aigov/agent/list` 返回 200，且能看到 4 个内置 Agent；
5. `GET /aigov/evaluation/case/list` 返回 7 条用例。

**启动失败时先看什么**（按最可能顺序）：

- `BeanCreationException` / `NoSuchBeanDefinition` → 某个 WP3 服务没被扫描到（包路径是否在组件扫描范围内）；
- `ApplicationContextException: Ambiguous mapping` → 路由冲突（本次已确认 9 个控制器前缀互不重叠）；
- `MyBatisSystemException` / mapper 相关 → Mapper 扫描或 `@Select` 解析问题（本地探针已用真 SqlSessionFactory 验过 8 张表）；
- 中文乱码或 1366 → **目标库不是 utf8mb4**（见附录 A.3）。
