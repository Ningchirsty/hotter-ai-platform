## 一、开场：三句话讲清这套系统

### 1.1 一句话

> **这是一条"把 AI 能力从'某个人的提示词'变成'受治理、可发布、可追溯的岗位能力'的流水线"。**

主线的形状（培训时画这一条线就够）：

```
注册（Agent/Skill/Package）→ 过五道门槛 → 发布 → 员工在「AI 工作台」看到岗位卡片 → 点启动
                    ↑
       训练台：草稿 → 与培训助手对话 → 变更提案 → 人工采纳 → 预检 → 提交
                    ↑
       草案生成器：技能/子Agent/快捷指令草案 → 生成一份可提交内容
```

### 1.2 ★一条贯穿全场的规矩（这是这套系统最特别的地方）

> **机器可以"提议"，但不能"生效"。**
> - 培训助手只产**提案**，改草稿必须由**人**点"采纳"；
> - 采纳 ≠ 发布：发布仍要走五道门槛；
> - 五道门槛里**四道要"库里有证据"**，只有「三方人工批准」是**声明式**的（平台不核对批准记录）。
>
> 讲这句的时候要停一下，因为它决定了后面所有界面的样子：
> **凡是"机器给的东西"，界面上一定有一处要你点确认。**

### 1.3 三种账号能做什么（用真实权限集，不是推测）

| 能力 | `aig_admin` | `aig_security` | `aig_viewer` |
|---|---|---|---|
| 看治理台（Agent/Skill/Package/评测/绑定/审计/配额/令牌） | ✅ | ✅ | ✅ |
| 推进发布状态 / 绑定管理 / 工具知识绑定 | ✅ | ❌ | ❌ |
| Package 上传 / 安装 / 停用 | ✅ | ❌ | ❌ |
| Manifest 扫描 | ✅ | ✅ | ❌ |
| **服务令牌：签发 / 停用** | ✅ | ✅ | ❌（只能看清单） |
| **查看模型密钥引用**（`aig:model:secret`） | ✅ | ✅ | ❌ |
| 调用授权：申请 / 审批 | ✅ / ✅ | ✅ / ✅ | 只能申请 |
| **训练台**（草稿/预检/提交/测试） | ✅ | ❌ | ❌ |
| **与培训助手对话 / 采纳提案 / 草案生成器** | ✅ | ❌ | ❌ |
| AI 工作台 / 我的资产 | ✅ | ✅ | ✅ |
| 权限点数量（★口径见下） | **通配 `*:*:*`（实际不受限）**；其角色被授予的 `aig:*` 去重 **63 个** | **23 个 `aig:*`** | **17 个 `aig:*`** |

★**上表最后一行的口径必须讲清**（不然学员会算错）：
- `aig_admin` 的 `getInfo` 实测**只回 1 条**：通配符 `*:*:*` —— 所以"admin 有多少个 aig 权限点"这个问法本身没意义；
  63 是**他角色被授予的菜单/按钮**去重后的数；
- `aig_security` / `aig_viewer` 的 23 / 17 也是**同一口径**（角色已授权菜单去重）——三个数可以横向比；
- `getInfo` 返回的权限数组是**去重**的（实测 steven：125 条 = 125 个唯一值）。

★**两个必须当场纠正的误解**：

1. **`aig_security` 不是"只读角色"**——它能**签发服务令牌**、能**看密钥引用**、能**跑 Manifest 扫描**。
   培训时别说成"安全审计只看看"。
2. **`steven` 不是低权限账号**——他实测有 **125 个权限点**，含整套 `aig:agent:*`。
   （他**只**是没有 `/system/*` 系统管理权，那是另一回事。）要演示"无权限被 403"，
   必须用一个**只挂 `aig_viewer`** 的账号。

### 1.4 界面上的红色提示 = 设计，不是故障

这套系统大量使用 **fail-closed**（宁可不做，不可做错）。所以培训时要预先打预防针：

> **看到"拒绝"先看它有没有点名原因。** 好的拒绝长这样：
> `只有草稿责任人可以和培训助手对话：draftId=2109588540042022913，责任人=2100581336629641218`
> 它同时告诉了你：**为什么被拒**、**哪个对象**、**该找谁**。
> 而**没有信息的"发生未知异常"**才是故障，要按 §十 上报。

### 2.2 登录相关的三个体感（培训时学员一定会问）

| 现象 | 原因 / 说法 |
|---|---|
| 用着用着突然"登录已过期，请重新登录" | 会话约 **30 分钟**（实测）。演示前先登一次 |
| 界面突然全 403、菜单少了 | 管理员刚改过你的权限——**必须重新登录**（权限在会话里缓存） |
| 管理员把你删号了，你还能用一会儿 | **删用户 ≠ 踢下线**：已签发的会话按自己的 TTL 活着。规范收尾是**删用户 + 强制下线**两步（见 §3.6） |

### 2.3 看不到某个页面怎么办

1. 先确认**角色**有没有那个**菜单权限串**（见 §1.3 / 菜单管理）；
2. 改完让本人**重新登录**；
3. 还是看不到 → 可能是**按钮级权限**（同一个页面上不同按钮的权限串不同，例如
   工具/知识绑定页：**看清单**要 `aig:agent:list`，**新增/删除**要 `aig:agent:resource-binding`）。

## 三、主线一：治理台（管理员/安全角色培训）

### 3.1 注册中心：先分清四样东西

| 对象 | 是什么 | 培训时的一句话 |
|---|---|---|
| **Agent** | 一个岗位 Agent 的定义 | "这个人是谁" |
| **Agent 版本** | 定义的某一次不可变快照 | "这一版的他长什么样" |
| **Skill** | 可复用的技能 | "他会的手艺" |
| **Package** | 打好的包（带 Manifest） | "把技能/Agent 打包安装给别人" |

### 3.2 ★五道门槛（本级最重要的一页）

在「Agent注册中心」选中一个版本 → 点「推进发布状态」→ 弹窗里勾选已满足的门槛。

| 门槛 | 要不要证据 | 证据来自哪里 |
|---|---|---|
| Manifest 校验 | **要**（★只对 **Package 版本**生效；Agent/Skill 版本不带 Manifest，所以那道门槛对它们是**声明式**的） | 该版本库里的 `scan_result` |
| 沙箱运行 | **要** | 沙箱运行账本（`aig_sandbox_run`） |
| 黄金用例 | **要** | 评测账本 |
| 灰度达标 | **要** | 调用统计 |
| 「三方人工批准」 | **不要（唯一例外）** | **平台不核对批准记录**——勾它就等于声明"线下已批" |

★★**弹窗上其实有三处都写明了这件事**（顶部说明 / 勾选区提示 / 确认弹窗）。培训时**照弹窗念**，
不要讲成"都会去库里核对"——那会让人以为"人工批准"也有记录可查。

★**实操提醒**：没有证据的声明会被**明确拒绝**并保持原状态。例如对 `VALIDATED` 版本声明"沙箱已跑通"会得到：

```
不允许声明「沙箱已跑通」而库里没有证据：该版本没有任何沙箱运行记录。
实测：没有任何运行记录。请先在宿主机跑一次沙箱作业（script/deploy/sandbox-worker.sh），
把执行器输出的 result.json 原样登记进来（对象 AGENT_VERSION #…）
```

### 3.3 评测：黄金用例 → 跑评测 → 人工复核

- 「定义黄金用例」→「跑评测」→「评测人工复核」是**三个独立权限点**（`aig:evaluation:define/run/review`）——
  说明"谁能定义标准"和"谁能判分"是分开的，培训时要讲这个分工。
- 生成物能不能过「预检」，是"可提交"的硬判据。

### 3.4 适配/路由/模型：改之前先想清楚

「路由策略」「模型注册中心」「AI 能力目录」是**影响所有调用**的地方。
- 改模型/路由会**立刻影响线上调用**，演练时**只看不改**；
- `aig:model:secret`（看密钥引用）只授给 `aig_admin` / `aig_security`——**讲"谁有权看密钥"**。

### 3.5 审计与配额/授权

- **调用审计**：每一次模型/工具外发都有一行（"为什么放行/为什么拒绝"可举证）。
  培训时演示"用一次对话 → 去审计里找到那一行"。
- **调用配额**（按人按周期限次）、**调用授权**（人 × 能力 × 数据等级，带时效）：
  讲"不是有权就能无限用"。

### 3.6 ★服务令牌：三个必须讲清的操作规矩

入口：`/admin-center/ai-gov/service-token`。它是**机器身份**（给系统对系统调用用的）。

1. **调用方要带两个头**：`X-Service-Token`（令牌）+ `clientid`（平台约定）。**缺 clientid 直接 401**。
   ★不是 `Authorization` —— 这一点讲错会让集成方排查很久。
2. **生效范围只有 `/aigov/*`**。同样的令牌打 `/system/*`、`/content/*` 会得到
   `401 登录状态异常`（过滤器不在那些路径上）——**不是令牌坏了**。
3. **轮换顺序**：**先签发新令牌 → 调用方切换 → 再吊销旧的**。顺序反了会有一段全部 401。

★**收尾规矩（实测两次）**：**删用户不会让已签发的会话失效**。
清一个测试账号要 **两步**：①删用户 → ②`在线用户`里对它**强制下线**。
只做第一步，那个人的令牌在 TTL 内**还能用**。

### 3.7 工具/知识绑定：这是"声明的收窄"，不是第二条声明通道

入口：`/admin-center/ai-gov/resource-binding`。

**四句话讲清它**：
1. 版本上写了"这个 Agent 能碰哪些工具/知识"（`allowed_tools` / `knowledge_scope_json`）；
2. 绑定表只说"这些声明里，**在什么范围下**（公司/品牌/场景/角色）真的给它用"；
3. **编码必须命中已声明的项**，而且 `forbidden_tools` 里的**一律拒绝**——
   否则治理台说"不能用 shell"、绑定表却给它绑上，就没人说得清以哪个为准；
4. **它只登记、不执行**（本仓没有 Tool Gateway / Knowledge 引擎；绑定不会让任何工具真的能跑）。

**你会看到的校验与文案**：

| 操作 | 结果 |
|---|---|
| 绑一个未声明的编码 | 拒绝，并提示只能绑该版本已声明的项（会列出 `allowed_tools` 实际内容） |
| 绑一个版本没声明任何东西的版本 | 提示"**先去声明**"（而不是含糊的"没匹配上"） |
| 同范围重复绑 | `同一条绑定已存在：版本 … 的 TOOL「…」在相同范围下只能绑一次（要改范围请删掉旧的那条再建…）` |
| 换范围再绑同编码 | **允许**（这是常规做法） |

★★**新增能力（2026-10-13）：可以把绑错的那条删掉再建。**
- 列表每行有「删除」→ 弹二次确认 → 确认后该行消失；
- 确认文案会说清三件事：**删的是哪一条**（类型+编码）、**它的范围**、**删完能不能重绑**；
- **删除是逻辑删除**：行还在库里（可追溯），但"同一范围"的名额**立刻放掉** ⇒ 可以马上重建；
- ★**没有"停用"**：`enabled` 只在创建时能设——因为本表没有执行语义，"停用"没有运行效果，
  反而会占着名额把人卡住。要"暂时不用"就**删掉，需要时再建**。

## 四、主线二：训练台（★本轮"细节体验"最多的地方）

入口：`/admin-center/ai-gov/studio`（需要 `aig:studio:draft:list`，实际动手还要各按钮的权限点）。

### 4.1 草稿与修订

| 概念 | 一句话 | 界面上能看到的 |
|---|---|---|
| 草稿 | 版本的工作稿 | 列表里的 `agentCode` + 责任人 |
| 修订 | **不可变**快照（每次保存 +1） | 「修订历史」里能看到编号与来源 |
| 来源 | 谁产生的这一版 | `MANUAL`（人手改）/ `COPILOT_ACCEPTED`（采纳了助手提案）/ `DRAFT_GENERATED`（草案生成器生成） |
| 回滚 | 回到某个旧修订 | 会**产生一条新修订**（不删历史） |
| 归档 | 停止使用 | 归档后：**不能再提提案、不能再对话** |

★培训要点：**"修订历史"就是这份草稿的账本**。任何"内容怎么变的"都能回答。

### 4.2 与培训助手对话（会产提案，也可能花钱）

入口：**提案面板底部的「与培训助手对话」**（默认收起，且按钮上标注"会花一次调用"）。

**三重限制，缺一不可**（培训时必须逐条讲）：

| 限制 | 不满足时的文案 |
|---|---|
| ① 功能开关开着 | `对话式 Copilot 当前是关闭的（aigov.studio.copilot.enabled=false）…` |
| ② 你的账号有 `aig:studio:copilot:chat` | **403 没有访问权限** |
| ③ **你必须是这份草稿的责任人** | `只有草稿责任人可以和培训助手对话：draftId=…，责任人=…` |

★**第③条是"在花钱之前"挡住的**——实测用非责任人账号发起对话时，
**模型网关审计行数没有增加**（说明根本没调模型）。培训时这句话很值钱：
> **"没权限就不会先扣费再告诉你没权限。"**

**每次对话的三种结论**（都能在「会话历史」里看到）：

| 结论 | 什么意思 | 培训时怎么说 |
|---|---|---|
| `SUCCEEDED` | 产出了一条**待审提案** | "它提议了，去看提案面板" |
| `REJECTED` | 模型想改**不该改的字段**（如 `providerCapability`） | "★这是最该被看见的信号：说明提示词没约束住模型" |
| `FAILED` | 模型没调通 / 输出解析不了 | "会带可读原因，不是空白" |

★**数据等级必须每次指定**（`PUBLIC/INTERNAL/STRICT/RESTRICTED`），网关按它判外发许可。
**不要把等级调低来"让它能跑"**——这句话要原样讲给学员。

★**费用口径（讲准，别吓人）**：生产当前命中**本地部署**（`deploymentType=LOCAL`），
**不产生外部 API 计费**；但**如果后续路由到外部供应商，每一次对话都是一次真实计费调用**。
⇒ 所以演练时：**只讲一次、不要连点**。

### 4.3 ★变更提案面板（交互细节，逐条对照打勾）

| 交互 | 你会看到什么 | 为什么这样设计 |
|---|---|---|
| 打开面板 | 列出提案（最新在前），含状态与改动预览 | — |
| **点「刷新」** | **当前选中被清空** | 列表变了以后，"选中"很可能指向一条已经不在列表里的提案 |
| 选中一条**已拒绝/已采纳**的提案 | **采纳/拒绝按钮变灰不可点** | 只有"**待处理 ∧ 草稿未归档**"才可操作 |
| 草稿**已归档**时 | 两个按钮都不可点 | 已归档的草稿不能再改 |
| **切换到另一份草稿** | **对话区自动收起、输入框清空** | 避免把 A 草稿的对话误发到 B 草稿上 |
| 点「采纳」 | 弹二次确认；成功后**修订号 +1**、来源显示 `COPILOT_ACCEPTED` | 采纳 ≠ 发布 |
| 点「拒绝」 | 草稿内容**不变** | — |

**必然遇到的四种拒绝**（都值得现场演示一次）：

| 你做了什么 | 文案（节选） | 说明 |
|---|---|---|
| 用旧修订提提案 | `提案基于的修订已不是当前修订：baseRevision=…` | 别人已经改过了 |
| 提完提案后内容被改，再采纳 | `提案提出后草稿内容已变化，提案失效（内容哈希不一致）：…` | ★**更隐蔽的一条**：编号对得上、内容漂移了 |
| 提一个"改完和原来一样"的提案 | `提案没有产生任何内容变化：所给的值与当前内容一致` | 防"空转提案" |
| 处理别人草稿的提案 | `只有草稿责任人可以处理它的变更提案：draftId=…` | **采纳和拒绝两条路径都拦** |

★**还有两句容易被误判的**：
- 同一路径在一次提案里出现两次 → `同一路径在提案里出现了多次：/agentName（哪一次算数会取决于顺序，平台不接受这种歧义）`；
- 提案里有一处改动**没有路径** → `提案里有一处改动缺少路径（path）`；
  （★操作项整个为 `null` 时才是 `提案里有一处改动为空`——两句是不同输入的不同文案）

### 4.4 草案生成器：三类草案 → 预览 → 生成到草稿

入口：`/admin-center/ai-gov/artifact-draft`。三个页签：**技能草案 / 子 Agent 草案 / 快捷指令草案**。

**流程**：选页签 → 新增草案 → 点「预览」→ 填**目标草稿ID + 期望修订号** → 点「生成」。

**预览弹窗里你会看到**（这几个是培训的"亮点"，要专门点开看）：

1. **八个 Prompt 分节永远都在**——没填的显示成灰色的 **「空」** 标签，**不会消失**
   （设计意图："让人看到这一节是空的"，而不是让人以为生成器没填）；
2. **「生成说明」列出"没进生成内容"的字段**，例如：
   - 父 Agent 编码「…」是 Agent 定义上的归属关系，草稿内容里没有这个槽位…
   - Agent 编码「…」不在草稿内容里：提交时用的是训练台草稿自身的编码…
   - 启动方式（`launchMode=`）/启动目标（`targetType=`、`targetRef=`）属于**岗位卡片**配置，不在草稿内容里…
3. **没有假占位**——不会出现「（待补充）」这种顶替真实字段值的文案；
   "留空待补充"只作为**数量**说明出现（如"N 节留空待补充"）。

★**两张必须打预防针的牌**：

| 事实 | 怎么讲 |
|---|---|
| **草案编码不能重复** | `技能草案编码已存在：…（编码是页面上认出草案的唯一方式，不能重复）` |
| **生成 ≠ 可执行** | 生成只产出**一份可提交内容 + 一条草稿修订**，**不会**产生任何可执行版本；提交/发布仍要人显式操作 |
| ★**非法 `promptSectionsJson` 创建时不会被拦** | 创建时**照存**（草案可以先存半成品），**预览/生成时**才拒：
`草案无法生成：promptSectionsJson 必须是 JSON 对象（分节键 → 正文）` / `…不是合法 JSON：…`。
**这是已裁定的现状**（2026-10-13 用户选择保持），培训时讲成"校验在用的那一刻"，别讲成"创建就该拦" |
| **目标草稿 + 期望修订号必须对** | `expectedRevision` 过期 → 拒绝，**不会覆盖别人的修改** |

## 六、见到这句话 = 发生了这件事（拒绝文案对照）

> 培训时建议打印这一页。**先看文案，再下结论**——本系统的拒绝文案基本都点名了原因。

| 你看到的文案（节选） | 实际发生了什么 | 下一步 |
|---|---|---|
| `登录状态异常，请重新登录` | 未登录 / 会话过期 | 重新登录 |
| `没有访问权限，请联系管理员授权` | 已登录但**缺权限点** | 找管理员加权限点，**然后重新登录** |
| `请求地址不存在` | 路径写错 / **该端点不在这个镜像里** | 确认版本（见 §十） |
| `发生未知异常，请联系管理员 [错误编号: N]` | **真故障**（服务端异常） | 记下编号 + 时间，按 §十 上报 |
| `只有草稿责任人可以和培训助手对话：draftId=…` | 你不是这份草稿的责任人 | 换责任人操作，或改草稿责任人 |
| `只有草稿责任人可以处理它的变更提案：draftId=…` | 同上（采纳/拒绝都拦） | 同上 |
| `草稿已归档，不能再对话 / 不能再提提案：draftId=…` | 草稿已归档 | 复制成新草稿再改 |
| `提案基于的修订已不是当前修订：baseRevision=…` | 草稿被别人改过了 | 刷新后重新提 |
| `提案提出后草稿内容已变化，提案失效（内容哈希不一致）` | 编号对得上但内容漂移 | 重新提 |
| `提案没有产生任何内容变化：所给的值与当前内容一致` | 提案等于没改 | 改点别的 |
| `变更提案已被处理过：<状态>` | 已被采纳/拒绝 | 刷新看状态 |
| `同一路径在提案里出现了多次：/…` | 一次提案里同一个字段写了两次 | 合并成一处 |
| `草案编码已存在：…` | 草案编码重复 | 换个编码（编码是页面上认出草案的唯一方式） |
| `未知的草案类型：foo；可选：skill / child-agent / action` | `kind` 写错 | 用可选值之一 |
| `目标草稿的内容与生成结果一致，未产生新修订` | 生成结果和目标草稿一样 | 正常，不用重试 |
| `同一条绑定已存在：版本 … 在相同范围下只能绑一次` | 同范围重复绑定 | **删掉旧的那条再建**（现在可以了，见 §3.7） |
| `工具/知识绑定不存在或已删除：<id>` | 删一个已经删过的 | 正常（幂等），刷新列表即可 |
| `服务令牌无效、已停用或已过期` | 机器身份的令牌不可用 | 重新签发，注意**轮换顺序** |
| `缺少 clientid 请求头：…` | 集成方少带了一个头 | 提示他要带 `X-Service-Token` + `clientid` |
| `不允许把令牌管理权限（aig:service-token:issue）签发给机器身份…` | 想给机器"自我续期"的能力 | 设计如此：令牌管理必须由**人**的账号做 |
| `不允许声明「沙箱已跑通」而库里没有证据：…` | 声明式勾选但库里没记录 | 先真跑一次沙箱作业再登记 |

## 九、九个必须当场纠正的误解

1. **"点了采纳就发布了"** ❌ ——采纳只改**草稿**，发布仍走五道门槛。
2. **"人工批准也有记录"** ❌ ——它是**唯一声明式**的门槛，平台**不核对**批准记录。
3. **"绑定表能让工具真的跑起来"** ❌ ——本表**只登记、无执行语义**。
4. **"`aig_security` 是只读角色"** ❌ ——它能签发服务令牌、看密钥引用。
5. **"`steven` 是低权限账号"** ❌ ——他有 125 个权限点（只是没有 `/system/*`）。
6. **"服务令牌放 `Authorization` 头"** ❌ ——是 **`X-Service-Token`**，且必须带 `clientid`。
7. **"令牌打别的接口 401 = 令牌坏了"** ❌ ——过滤器只在 `/aigov/*` 上，别的路径本来就不认它。
8. **"空列表 = 我没有资产"** ❌ ——先点一次「刷新索引」；它来自**派生索引**。
9. **"草案生成器生成完就能用了"** ❌ ——生成只产出一份**可提交内容**；提交/发布都要人显式做。

## 十、出问题时怎么判（故障 vs 自己的请求错）

**看到 4xx/5xx 时，先按这个顺序怀疑**（实战总结，别跳步）：

| 现象 | 先怀疑 | 怎么排除 |
|---|---|---|
| `401` | 没登录 / 会话过期 / **服务令牌用错头** | 换会话令牌再试；确认头名 |
| `403` | 权限点不够 | 让管理员对比 §1.3 的权限集；**改完要重新登录** |
| `404 请求地址不存在` | 路径写错，**或该功能不在当前镜像里** | 与"这个版本该有的功能"对照；★**注意**：路径变量有正则的（如 `/resource-binding/{id:\d+}`）传非数字也是 404 |
| `405` | **HTTP 方法用错**（例如 `chat` 是 POST，不是 GET） | 换方法 |
| `500 发生未知异常 [错误编号: N]` | **真故障**；但**先看是不是少传必填参数**——本仓会把参数缺失也掩成 500 | 补上必填参数重试；仍 500 才是故障 |
| `code=403/500` 却是 HTTP 200 | **正常**：本仓业务异常统一以 `HTTP 200 + code!=200` 下发 | 看 `code` 与 `msg`，别看 HTTP 状态 |
| "我明明改了权限，还是看不到" | 权限在**会话里缓存** | 让本人**重新登录** |

**上报要带这四样**（不讲这四样，排查会绕远）：

1. **时间**（到分钟）+ 谁操作的（账号）；
2. **`[错误编号: N]`**（有就必给）或完整的 `code` + `msg`；
3. **页面 URL**（本手册 §2.1 的真实 URL）+ 点了哪个按钮；
4. **是不是必填没填 / 方法用错**（自己先排除一次）。
