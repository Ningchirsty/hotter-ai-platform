**加了构建期守卫，防止这类错再发生**（`AigPermissionSeedCoverageTest` 新增 2 条）：

1. `menuSeedIdsAreUnique`：扫描 `script/sql/*.sql` 里每条 `insert into sys_menu (…)` 的 menu_id，
   **同一文件内重复** → 红；**跨文件撞 ID 但声明成不同权限行** → 红。
2. `collisionDetectorItselfWorks`：拿一段带重复 ID 的样例喂给检测器，断言它**确实报 1 处**；
   再用干净样例断言不误报。（原因同该测试类里原有的 `repoRootIsLocatable`：
   检测逻辑本身要有断言，否则整个守卫会静默变成空转。）

> 为什么原有的 `everyPermissionConstantIsSeeded` 没抓住：它只看"权限串在脚本文本里出现过"，
> 而这个错是"**行没插进去**"——文本层面完全正常。这两件事必须分开查。

**验证**：把 ID 临时改回 `0024` 重跑该测试 → **确实变红**，报错点名两条 insert

**这次的教训（写给自己）**：核查结论里写"某脚本没执行"之前，要先能解释**为什么脚本跑了却什么都没发生**。
`insert ... where not exists` 这类"幂等守卫"在撞主键时会**静默吞掉整条语句**，
是"跑了但没生效"的经典成因——而它的症状（exit=0、无报错）与"没跑"完全一样。
