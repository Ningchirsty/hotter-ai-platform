## 1 一个关键实测结论（先看这条，它决定了 P0 的成本）

读代码后确认：**右侧试调助手所需的数据，后端已经全部在下发了**。

`POST /aigov/invoke/dryRun`（`AigInvokeController.java:67`）入参 `AigInvokeBo`
（`capabilityCode`、`dataLevel` 必填；`allowExternal`、`scenarioCode`、`agentVersionId`、`maxCost` 可选），
返回 `AigInvokeVo`（`AigInvokeVo.java`）已含：

| 字段 | 用途（助手要回答的问题） |
| --- | --- |
| `decision` | MODEL 命中 / MANUAL 转人工 / DENIED 拒绝 → "会走哪条路" |
| `modelKey` / `modelId` / `deploymentType` / `invoker` | "选中了谁、走的哪条链路" |
| `externalCall` | "这次会不会出域" |
| `reason` / `reasonCode` | 失败/受阻的文本与**细因编码**（`AigPolicyReasonCodeEnum`） |
| **`policyHits: List<String>`** | **路由 7 步逐条判定 +「哪些候选模型因何被排除」**（`AigRouteServiceImpl` 里 `decision.addHit("排除 modelId=…：生命周期=… 不可调用")` 等 10 余处） |
| `pendingConfirm` | 需要人工确认的结论点 |

⇒ **P0 的助手 = 纯前端**：把这套数据渲染成对话，并支持"假设试跑"（换 `dataLevel`/`allowExternal`/`scenarioCode`/`maxCost` 再跑一次 dryRun）。
**不需要新权限点**（沿用 `aig:capability:query`；权限拆分见 P1）。

> 更正：早前方案里写的"试调后端需补 `reason_code` 输出""需新增 `capability:trial` 权限"——**实测已存在 / 可留到 P1**，
> 不要在 P0 里重复造。

### 3.3 C 试调助手（右侧常驻对话）

**布局**：右栏（详情页内 `position: sticky`），头部 `能力试调助手 + 版本记录 + 展开/收起 + 折成浮卡`；
中部消息流；底部输入条（`＋ 上传` / 输入框 / `🎙 语音` / 蓝色发送）。
**空态**：吉祥物 + "很高兴为您服务" + 作用域说明 `当前作用域：{能力名}（{code}）· dryRun 不产生费用、不写审计`。

**快捷 chips → 对话契约（P0 固定 4 类）**

| Chip / 用户问题 | 前端动作 | 渲染（数据来自 dryRun） |
| --- | --- | --- |
| `会走哪条路？` | dryRun（用当前假设参数） | 六段式：① 能力校验 ② 策略命中（allowExternal/approval/fallback） ③ 候选与排序（PRIMARY→FALLBACK→GRAY） ④ **逐条排除原因**（`policyHits`） ⑤ 最终选择（`modelKey` + `deploymentType` + `invoker`） ⑥ 审计预览（真实调用会写哪些字段）+ 底部"本次未发起调用" |
| `为什么排除了 X？` | 同上；前端从 `policyHits` 中筛出含该模型键/ID 的行 | 逐条列出原因（生命周期不可调用 / 数据等级上限 / 健康 UNHEALTHY / allowExternal=N / 标签不匹配 / 未登记治理属性 / 超预算…）；**筛不到就明说"本次决策没有排除它"**，不猜 |
| `数据等级是严格会怎样？` | **换 `dataLevel=STRICT` 再跑一次 dryRun**（假设试跑） | 对比式回答：`严格 ⇒ 只允许非外部部署`，并列出"因此被排除的候选"与"是否转人工" |
| `生成策略建议` | 纯前端规则（P0 模板） | 基于 `reasonCode` + `policyHits` + 策略覆盖度给 2~4 条建议，**明确标注"建议，不会自动写入"** |

**自由输入**：P0 走"关键词路由到上面 4 类"（含"外发/审批/预算/场景"等词），命中不了就回一句模板并给出 4 个 chip；
**不接大模型**（治理台不应为了一次问答产生外部调用与费用）。

**假设参数条**（chips 下方一行，可折叠）：`数据等级`（默认 INTERNAL）· `禁止外发`（开关）· `场景`（下拉，可空）· `单次预算`（可空）。
> 这一条是"对话比表单好用"的真正原因：**任选一个假设直接跑，答案立刻出来**。

**错误处理**：dryRun 返回 `code!=200` → 气泡内显示 `reason`（红），并保留"原始返回"入口；网络失败 → 可重试按钮。

### 3.4 D 模型候选

列表列：模型（`modelKey` + 名称）· 用途（PRIMARY/FALLBACK/GRAY 胶囊）· 优先级 · 部署类型 · 健康（`health_status` + 探测时间）· 操作（编辑/停用）。
**编辑弹窗字段**（P0 必须补，现有只有 POST/DELETE）：

| 字段 | 规则 |
| --- | --- |
| 候选模型 | 只读（换模型 = 删了重建，避免语义漂移） |
| 用途 | 单选 PRIMARY / FALLBACK / GRAY，必填 |
| 优先级 | 整数 1~999，必填，同用途内建议唯一（重复只提示不阻断） |
| 启停 | 开关（`enabled`，P0 若表无该列则用状态列；**无列则不加列，改为"删除"即停用**） |

> 注：`aig_capability_model` 现有 `uk(capability_code, model_id)`，改用途/优先级不冲突；删除为物理/逻辑删除按现状。

## 8 回归用例清单（P0，共 26 条）

**A 能力清单（8）**
1. 列表默认按"配置完整度"排序，缺候选的能力排在最前；
2. 筛选"模型候选=无候选"只出无候选的能力，计数同步变化；
3. 清除筛选后回到默认排序与全量；
4. 能力数 > 200 时下拉不截断（服务端搜索 / 全量拉取，验证计数一致）；
5. 卡片 hover 出现菜单；菜单五项动作各自可达（试调/编辑/候选/提交审核/删除）；
6. 删除能力时给出引用影响提示（P0 为文案，P1 为校验）；
7. 空态在筛选无结果时出现，且主按钮可创建；
8. 未声明标签的能力显示灰色 `?` 图标与 `未声明标签` 胶囊。

**B 详情 + 试调助手（8）**
9. 详情页默认**收起**配置详情，只显示人设与状态；
10. 展开后 5 个页签均可切换，且"模型候选"空态显示插画 + 主按钮；
11. 助手空态显示作用域与"不产生费用"；
12. 点 `会走哪条路？` 返回六段式，**含逐条排除原因**，且末尾有"本次未发起调用"；
13. 点 `为什么排除了 X？` 能定位到对应模型的原因；**筛不到时明确说"本次没有排除它"**；
14. 点 `数据等级是严格会怎样？` 会用 STRICT 重跑并给出差异（含被排除项）；
15. 助手可折成右下浮卡、可再展开；
16. dryRun 失败时气泡显示可读原因 + 原始返回入口（不白屏）。

**C 候选与策略（4）**
17. 编辑候选用途（PRIMARY→FALLBACK）后，详情与列表反映新值；
18. 优先级重复只提示不阻断；
19. 策略页展示未配置的等级为灰底 `未配置`，可跳去新建；
20. 场景指定为空时显示"不按场景收窄"而不是空白。

**D 看板（3）**
21. 4 个指标与时间范围联动；
22. 排行榜可切换"调用最多/失败最多"；
23. 表格视图与卡片视图数据一致（同一接口）。

**E 权限与越权（3）**
24. 只有 `aig:capability:list` 的角色看不到"创建/编辑/删除/试调"按钮；
25. 只有 `aig:capability:query` 的角色可试调但不可编辑；
26. 无 `aig:route:*` 的角色在候选页为只读（不出现编辑入口）。

**既有回归**：`AigPermissionSeedCoverageTest`、`AigRepeatSubmitCoverageTest`、
`AigWp3WiringAndRoutesTest` 必须全绿（新增接口要补权限注解与路由断言）。
