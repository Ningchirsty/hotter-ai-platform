# 能力域 现状走读与重构方案（治理台 · 待确认风格稿）

> 触发：平台发布到生产后，反馈「能力这块很乱」。
> 范围：`ruoyi-modules/ruoyi-ai-gov`（后端）+ `script/sql`（数据/权限/菜单）+ `frontend/src/views/aigov`（前端）。
> 方法：3 路只读走读（后端实现 / 数据权限菜单 / 前端信息架构），全部结论带**文件:行**证据；未核实项单独列出。
> 风格参考：**DinTal / Aquila Pilot 数智员工平台**（华为云云商店，Aquaintelling）—— 按其**真实截图 24 张**逐屏解读，
> 借的是**Agent 设计思路与交互**：左栏"图标+小字"、顶部对象类型页签、创建卡 + 卡片网格 + hover 快动作、
> 详情整页（封面 + 配置渐进披露 + 右侧常驻对话助手）、看板彩色指标 + 排行榜、深色日志控制台、插画空态。
> 配色（蓝白 + 浅灰底 + 白卡片）只是其中一部分。
> 交付物：本文档 + 可点静态原型 **`治理台-能力域-demo-v3.html`**（v1/v2 保留对比）。**本稿不含任何业务代码改动**。

## 1 结论摘要（10 行）

1. 「乱」的根因**不是页面太多**，而是：**「能力」这个词在同一套界面里指三样东西**——
   ①业务能力编码 `capability_code`（路由与调用只认它）②Agent/Skill 声明的"所需能力" `provider_capability`
   （**其实是 ① 的别名**，列名与注释却写成 Provider 能力）③模型模态标签 `required_tags` / `capability_tags`。
2. 更关键：**决定路由的两个判据在界面上没有入口**——模型侧 `capability_tags`（前端 VO 直接丢掉该字段）
   与「能力×模型绑定」（后端有接口、自陈"前端未提供页面"）。于是"能力声明了模型却没有候选"这类故障
   只能改库或事后翻审计。
3. 因此生产上的典型体验是**「配了以为生效、其实没生效」**：能力模板里 `data_policy` / `input_schema` /
   `quality_threshold` 三列登记但从不参与判定；能力删除无引用校验 ⇒ 留下孤儿绑定/策略/审批。
4. 真实调用入口 `POST /aigov/invoke` 与"只看不花"的 `POST /aigov/invoke/dryRun` 都用
   `aig:capability:query` 授权，**"能查能力"= 能发起计费调用**；`aig:model:secret` 同时管"看脱敏引用"
   与"写/清密钥"，菜单名却叫「查看密钥引用」。
5. 导航是**20 个页面平铺**在「平台治理」下（无中间分组），`order_num` 有 `112`/`113`/`104` 三组冲突；
   与此同时页头还有**第二套硬编码的 4 项页签**（只覆盖能力/模型/路由/审计）挂在全部 12 个页面上。
6. 所有页面的 `h1` 都写「AI平台治理」，页与页之间**零跳转**；审计/绑定/任务里大量直出长数字 ID 与原始 JSON。
7. 同一概念四个名字共用「绑定」（能力↔模型、场景→供应商、Agent↔组织、版本↔工具/知识），
   权限、菜单、接口各指不同对象。
8. 交互规范各自为政：5 个页面无分页、3 个页面无 loading、20+ 处无空态、5 处危险操作无二次确认。
9. 数据层：场景绑定/配额/审批各有「全新库 + 存量库」两份 DDL；"健康状态"存在三套词汇
   （DDL 注释 `UP/DOWN/DEGRADED`、写入 `HEALTHY/UNHEALTHY`、读取 `DOWN/UNHEALTHY`）——历史上
   "测出坏模型自动避开"曾长期失效。
10. **收口方向**：命名归一 + 补齐两个断点（模型标签 UI、能力-模型绑定/试调）+ 导航从 20 项平铺收敛为
    **6 组 + 组内页签** + 权限边界正名。首批**不需要改数据模型**即可交付大部分收益。

## 3 现状的形状

### 3.1 主链路（后端真实判据）

```
①aig_capability(做什么,required_tags)
   └─②aig_capability_model(用哪些模型:PRIMARY/FALLBACK/GRAY+优先级)
        └─③aig_route_policy(能力×数据等级 → allow_external / require_approval / fallback_to_manual)
             └─④aig_route_scenario_binding(场景×能力 → 指定供应商,只收窄)
                  └─ AigRouteServiceImpl.decide()  → 有序候选
                       └─ AigInvokeServiceImpl.invoke() → 调用 + 审计 + 决策账本
横切: aig_model_governance(模型治理) · aig_call_approval(人×能力×等级授权) · aig_user_quota(按次数配额)
模型侧过滤: aig_model_governance.capability_tags  ↔  能力侧 aig_capability.required_tags   ← 界面缺口
```

### 3.2 界面的形状（前端真实结构）

```
管理中心 → 平台治理
 ├─ 20 个页面平铺（无分组）: 能力目录 · 模型注册中心 · 路由策略 · 调用审计 · AI任务 ·
 │   Agent注册中心 · 版本绑定 · Skill注册 · Package管理 · 黄金用例与评测 · Agent训练台 ·
 │   工具/知识绑定 · 岗位包管理 · 调用配额 · 草案生成器 · 调用授权 · 服务令牌 ·
 │   反馈与运营 · 知识中心 · 工具注册
 └─ 页头第二套导航: 只有 4 项（能力/模型/路由/审计），却挂在 12 个页面上
说明: 能力→模型→策略→调用 这条线，在界面上被拆到 6 个互不跳转的页面里
```

### 3.3 一句话

**能力域不缺功能，缺的是「一个词一个意思」和「一条线一个入口」**：值域、默认值、校验、读取方各写各的，
两个关键判据没有界面，用户只能靠猜与事后审计。

## 5 重构方案

> 分三层推进，**P0 完全不需要改数据模型**（改的是入口、界面与授权口径），这是本次建议的第一批范围。

### 5.1 第一层：命名归一（一张权威对照表，写进文档与界面文案）

| 权威概念 | 唯一名字（界面中文 / 代码字段） | 废弃/更正 |
| --- | --- | --- |
| 业务能力 | **能力** / `capability_code` | 不再用"所需能力/Provider 能力/技能能力"称呼它；`provider_capability` 列注释与 javadoc 更正为"业务能力编码（＝capability_code）" |
| 模型模态标签 | **模型能力标签** / `capability_tags`、`required_tags` | 不再与"能力"混用；值域收敛为一张枚举（建议：`TEXT / VISION / OCR / IMAGE / VIDEO / EMBEDDING / DECISION`，去掉已下线的 `RERANK`），并让 `AigProviderTypeEnum` 与之对齐或明确降级为"供应商自述" |
| 部署类型 | **部署类型** / `deployment_type` | 取值面统一为 5 值（含 `SELF`），修正 Bo 正则与 DDL 注释 |
| 四种"绑定"改名 | 能力↔模型 = **模型候选**；场景→供应商 = **场景指定**；Agent↔组织 = **可见范围**；版本↔工具/知识 = **资源收窄** | 菜单、接口路径、权限点同步改名（可保留旧路径做兼容） |
| 数据等级 | **数据等级**（公开/内部/限制/严格） | DDL 注释与 Bo javadoc 补 `STRICT` |

### 5.2 第二层：补齐两个断点（这是"乱"的直接来源）

1. **模型侧能力标签有 UI**：模型治理弹窗增加「模型能力标签」多选（值域＝5.1 的统一枚举），
   并在模型清单加一列"标签"；缺标签的模型在能力总览里直接标红（因为路由会因标签不匹配排除它）。
2. **能力×模型绑定有页面，且改为「模型候选」页签**：新增/改优先级/改用途（PRIMARY/FALLBACK/GRAY）/
   停用——**补充目前缺失的"编辑"能力**（现在只能删了重建）。
3. **试调入口（dryRun）**：在能力详情与策略页提供"试调"，输出"命中哪条策略 / 选中哪个模型 /
   排除了谁+原因（reason_code）"——把 `AigPolicyReasonCodeEnum` 里已预留但从未写入的原因码用起来。
4. **能力编码选择器**：训练台/草案生成器/授权/审计全部改为**带搜索的下拉**（含"不存在"的显式提示），
   取消手打；同时去掉 `pageSize:200` 的静默截断（改服务端搜索）。

### 5.3 第三层：信息架构（20 项平铺 → 图标竖栏 + 模块内页签）

**v2 起改按 DinTal 的导航范式**（详见 §6）：一级模块用**图标竖栏**（把文字收进 tooltip），
模块内用**顶部页签**切换视图——这一层与"20 项并排"的差别不是审美，而是**每屏只有一个入口集合**。

```
[图标栏]                 [模块内页签 = 视图]
🏠 能力          总览 · 能力清单 · 模型候选 · 调用试调 · 最近调用
🔲 模型与供应商    模型清单 · 供应商 · 健康与探测
🔀 路由与策略      数据等级策略 · 场景指定
📈 调用治理        调用审计 · 调用配额 · 调用授权 · 服务令牌
📦 资产登记        Agent 与版本（可见范围 / 资源收窄 页签）· Skill · 工具 · 知识 · Package · 评测
✨ 训练与运营      训练台 · 草案生成器 · 岗位包 · 反馈与运营
```

合并映射（原 20 页 → 新结构）：调用审计/配额/授权/服务令牌 → 「调用治理」四页签；
版本绑定 + 工具/知识绑定 → Agent 页内页签；Skill/工具/知识/Package → 「资产登记」页签；
训练台 + 草案生成器 → 「训练与运营」相邻两项（并互相跳转）；能力目录 + 路由策略 +（新增）模型候选/试调
→ 「能力」模块的五个页签。
同时统一：页头标题改为「模块 · 页面名」+ 面包屑；**删掉页头那套硬编码 4 项页签**（第二套导航），
或用同一份配置生成，不再手工维护。


### 5.4 权限边界修正（第一批就能做，纯授权口径）——**已落地（2026-10-16，`855b094f`）**

| 修正 | 做法 | 状态 |
| --- | --- | --- |
| 调用与查询分权 | 新增 `aig:capability:invoke`（真实调用）与 `aig:capability:trial`（dryRun）；`capability:query` 只读详情 | ✅ |
| 密钥查看/写入分权 | `aig:model:secret:view`（看脱敏）与 `aig:model:secret:edit`（写/清），菜单名与实际一致 | ✅（**运行期判定也拆了**：`canViewModelSecret` / `canEditModelSecret`） |
| 外呼测试独立 | `aig:model:probe`（连通性测试/批量探测）从 `model:edit` 拆出 | ✅ |
| 绑定权限归位 | 能力↔模型绑定改用 `aig:capability:candidate:*`（不再挂 `route:*`）；场景指定保留 `route:scenario` | ✅（更名 `route:binding`→`route:scenario`） |
| 菜单名与动作一致 | 「查看密钥引用」「治理属性编辑」「策略新增/删除」「调用授权审批」等 6 处改名或拆动作 | ✅ |

> 权限点新增需要种子脚本 + 菜单行，`AigPermissionSeedCoverageTest` 会强制"每个权限串有种子"，
> 因此这一步必须连同 `script/sql/aig_*_menu.sql` 一起改（**不需要改表结构**）。
>
> 落地方式（`script/sql/aig_permission_boundary.sql`，幂等）：**新权限点按 perms 反查 `sys_role_menu`
> 继承原权限点的全部角色**，改名用 `update ... where perms=旧值`（`menu_id` 不变 ⇒ 授权自动保留）
> ⇒ **除有意收紧的 `aig_viewer`（不再有 `invoke`，保留 `trial`）外没人掉权限**。
> ⚠️ 该脚本必须在**新镜像之前**执行，否则持旧权限的非超管会 403（见 doc24 §5「本版必做」）。
> **未做**：`approval:expire-scan` 拆权、服务令牌 scope 映射"调用人"——前者只是建议、后者是产品口径。

### 5.5 交互与展示规范（在 demo 里已可视化）

- **一屏回答一个问题**：能力总览＝"链路通不通"；策略页＝"能不能外发"；审计页＝"这次为什么这样"。
- **状态胶囊 5 类**统一（成功/警示/阻断/提示/停用），不再直出裸枚举与 `0/1`。
- **长 ID 与原始 JSON 默认折叠**（「显示原始字段」展开 + 可复制）；列表列值优先给人读的名称。
- **空态三行式**（图标 + 一句人话 + 下一步动作）；加载用骨架屏；列表统一分页与每页条数。
- **危险操作统一确认结构**：做哪件事 + 影响什么 + 能不能恢复（现有 5 处缺失一并补上）。
- **页间跳转**：能力 → 模型候选/策略/审计；审计 → 能力/模型；任务 → Agent 版本。长 ID 旁边给跳转。
- **配置健康度**贯穿：能力清单默认按"配置完整度"升序，缺模型候选/缺策略/孤儿配置直接可筛可点。

### 5.6 数据层建议（P2，需要迁移，先不动）

1. 「健康状态」词表统一为一个枚举（代码 + DDL 注释 + 存量数据一次 UPDATE）。
2. 默认值单一来源：`STATUS_NORMAL` / `DEFAULT_USAGE` / `DEFAULT_PRIORITY` / `DEFAULT_DATA_POLICY` /
   `DEFAULT_AUDIT_LEVEL` 收敛到常量或数据库默认，去掉 Java 与 DDL 双份。
3. 能力删除加引用校验（或改为"停用"）；场景编码加跨域校验（存在性 + 大小写归一）。
4. 三份重复 DDL 去重（保留"建表 + 迁移"单一来源）；`usageOrder` 等重复规则收敛为单一实现。
5. 能力模板的 `data_policy` / `input_schema` / `quality_threshold`：要么接入判定，要么在界面明确标"仅登记，不参与判定"。
