## 2. 权限与数据权限

### 2.1 权限校验
- 注解：`cn.dev33.satoken.annotation.SaCheckPermission`，业务 Controller 只实际使用 `@SaCheckPermission("模块:业务:操作")`；另有 `@SaCheckRole`、`@SaCheckLogin`、`@SaIgnore`、`orRole`（SaMode.OR）。
- 超管常量：`SystemConstants.SUPER_ADMIN_USER_ID = 1761100000000000001L`、`SUPER_ADMIN_ROLE_KEY = "superadmin"`（**无下划线**）。
- 前端下发：`GET /system/user/getInfo` → `permissions`（超管 `*:*:*`）、`roles`（超管 `superadmin`）。

### 2.2 数据权限（**人才库不使用，理由见下**）
- 注解打在 **Mapper 接口方法**（含 `default` 方法）上，**不是 Service**；注解**不继承**（`DataPermissionPointcut.java:24-34` 显式声明）。
- `@DataPermission({@DataColumn(key="deptName", value="dept_id"), ...})`，`joinStr` 默认 select 用 `OR`、update/delete 用 `AND`。
- `DataScopeType` 是**封闭枚举**（code `1`–`6`）：`ALL / CUSTOM / DEPT / DEPT_AND_CHILD / SELF / DEPT_AND_CHILD_OR_SELF`，`sqlTemplate` 与 `elseSql` 为 `final`。**新增第 7 种数据范围必须改框架源码。**
- **致命陷阱**：接口标了 `@SaCheckPermission` 后，只有"在 `sys_role_menu` 中绑定了该 perms 的角色"参与数据范围计算；一个都没匹配时返回 ` 1 = 0 `（**静默空结果，不报错**）。无注解的接口则全部角色参与。
- 忽略数据权限：`DataPermissionHelper.ignore(Runnable/Supplier)`。

### 2.3 人才库的决策：**不使用框架数据权限，改为服务端显式区域过滤**
理由（三条硬证据）：
1. `DataScopeType` 的 6 个模板只覆盖 `dept_id` / `create_by`，**无法表达 `region_code`**，扩展必须改框架源码 → 与"只开发人才领域能力、不改系统模块"的设计前提冲突。
2. 框架数据权限的生效依赖 `sys_role_menu` 里"角色↔权限标识"的绑定关系，一旦运维漏配就会**静默返回空结果**，故障不可观测。
3. 设计文档 §4.3 本身要求"列表查询必须追加区域可见范围 + 按 ID 二次校验"，这本就是服务端显式逻辑。

**落地方式**：`TalentScopeHelper` 作为唯一权威实现（区域集合、可写区域、单条授权、完整手机号），人才库 Mapper **一律不加 `@DataPermission`**。

## 3. 脱敏、加密、翻译

| 能力 | 结论 | 证据 |
|---|---|---|
| 脱敏注解 | `@Sensitive(strategy = SensitiveStrategy.PHONE, roleKey = {...}, perms = {...})`，`@Target(FIELD)` | `Sensitive.java:12-33` |
| 脱敏策略 | `ID_CARD / PHONE / ADDRESS / EMAIL / BANK_CARD / CHINESE_NAME / FIXED_PHONE / USER_ID / PASSWORD / CAR_LICENSE / FIRST_MASK / STRING_MASK / MASK_HIGH_SECURITY / CLEAR / CLEAR_TO_NULL` | `SensitiveStrategy.java` |
| 生效链路 | `ResponseEnhancementAdvice`(ResponseBodyAdvice) → `JsonValueEnhancer` → `SensitiveJsonFieldProcessor`，基于 **Jackson 3（`tools.jackson`）**，**只对 String 字段 + `application/json` 生效** | `ruoyi-common-sensitive` |
| 默认实现 | **`SysSensitiveServiceImpl` 确实存在**（`ruoyi-modules/ruoyi-system/.../SysSensitiveServiceImpl.java:18`）：命中 `roleKey` 或 `perms`，或 `LoginHelper.isSuperAdmin()` → **不脱敏**；否则脱敏 | 同上 `:27-45` |
| 加密注解 | `@EncryptField`（`org.dromara.common.encrypt.annotation`），前缀 `mybatis-encryptor`，**`enable` 默认 `false`**，默认算法 `BASE64`（等于没加密） | `application.yml:136` |
| 加密适用性 | 只支持"写入加密 + 按主键读解密"；**Wrapper 条件值不走加密拦截器，String 参数被显式排除** → **不适合等值/模糊/唯一索引查询** | `ruoyi-common-encrypt` |
| 翻译 | `@Translation(type = TransConstant.DICT_TYPE_TO_LABEL, other = "字典type")`、`USER_ID_TO_NAME`、`DEPT_ID_TO_NAME`、`OSS_ID_TO_URL` | `ruoyi-common-translation` |

> **对 B 号侦察稿的纠错**：B 稿第 7 条称"`SensitiveService` 只有接口、无任何实现，脱敏默认不生效"。经复核，**该结论错误**——`SysSensitiveServiceImpl` 存在于 `ruoyi-system`，且已注册为 `@Service`。人才库无需自己提供该 Bean，直接使用 `@Sensitive(perms = {...})` 即可。

**手机号方案（据此确定）**：
- 存储：`phone_cipher`（`@EncryptField` 密文）**+** `phone_hash`（SHA-256(盐+标准化号码)，用于重复预检等值查询）**+** `phone_tail4`（弱匹配）。
- 展示：VO 里的明文 `phone` 字段挂 `@Sensitive(strategy = PHONE, perms = {talent:profile:phone})`。
- 前提：需将 `mybatis-encryptor.enable` 置 `true` 并配置 AES 密钥；未开启时密文字段等同于明文，**上线前必须校验该项**（已列入验收清单）。

## 4. 对象存储（OSS）

| # | 结论 | 证据 |
|---|---|---|
| 1 | 6.0.0 只有 **一个 S3 客户端实现** `DefaultOssClientImpl`；MinIO / 腾讯 COS / 阿里云 OSS / 七牛 / 华为 OBS **全部走 S3 兼容协议**，无厂商专属客户端 | `ruoyi-common-oss/client/`、`pom.xml` |
| 2 | `application.yml` 中**没有任何 OSS 配置**；配置全部来自数据库 `sys_oss_config` → 缓存 JSON → `OssProperties`。`is_https` 实际生效值是 `Y/N` | `OssFactory.java:50-55` |
| 3 | 私有桶由 `sys_oss_config.access_policy='0'` 驱动，`matchingUrl` 会自动把 URL 换成 **120 秒**预签名地址；种子数据默认 `'1'`（公读） | `SysOssServiceImpl` |
| 4 | 自定义域名预签名（6.0.0 新增 `AwsV4HttpSigner` 路径）**仅在 `domain_url` 非空且 `bucket == 默认桶`时生效**，否则回退 SDK `S3Presigner`（URL 含桶名） | `ruoyi-common-oss/util/BucketUrlUtil.java` 等 |
| 5 | **`ISysOssService.upload` 的调用方无法指定对象键**（写死 `buildPathKey(originalFileName)` → `[prefix/]yyyy/MM/dd/<uuid><ext>`）；但底层 `OssClient` **提供自定义 key 的 `upload(String key, ...)`** | `ISysOssService` vs `OssClient.java:471,481,490` |
| 6 | 全仓**没有分片上传 / 断点续传**接口 | 全仓 grep 零命中 |
| 7 | `OssClient` **没有 copy/move 接口** | `OssClient.java` 全量 |
| 8 | 业务表关联官方写法是存 `oss_id`(bigint) + `@Translation(OSS_ID_TO_URL)`（如 `sys_user.avatar`） | `ry_vue.sql` |
| 9 | 框架下载接口 `GET /resource/oss/download/{ossId}` 只校验 `system:oss:download`，且 `IoUtil.readBytes` **全量进内存**（非流式、无 Range） | `SysOssController.java` |
| 10 | `deleteWithValidByIds` 的 `isValid` 分支为空（**无引用校验**），无 `@Transactional`，删除路径无 `@CacheEvict`，`sys_oss` 无软删字段 | `SysOssServiceImpl.java` |

### 由此确定的附件架构决策
1. **人才附件不登记进 `sys_oss`**：直接用 `OssFactory.instance(...).upload(customKey, ...)` 写入 `talent-private/` 前缀对象，元数据只存 `tl_talent_attachment`。
   - 理由：若简历登记进 `sys_oss`，任何拥有 `system:oss:download` 的账号可枚举 `ossId` **绕过人才库单条授权**下载简历。
   - `tl_talent_attachment.oss_id` 保留为可空列，便于将来双向登记。
2. **对象键可控**：`talent-private/{talentId}/{attachmentId}/v{version}/original{ext}` —— 先取雪花 ID 再上传，保证 key 稳定。
3. **无物理隔离区**：`OssClient` 无 copy/move，改为 `scan_status` 状态机，"扫描通过前禁止下载"达到同等安全效果（详见实现规范 §6.4）。
4. **受控下载走服务端流式代理**，不下发预签名 URL 给浏览器（避免 URL 进入日志/Referer）。预签名能力仅作后台优化预留。
5. 存储抽象：`TalentProperties.ossConfigKey` 为空用默认配置，非空用 `sys_oss_config` 中指定的专用配置 → **MinIO 与腾讯 COS 均可在不改代码的前提下切换**（二者都是 S3 兼容）。

## 6. 新业务模块接入清单（零框架改动）

以 `ruoyi-modules/ruoyi-system` 为样板：

1. 新建 `ruoyi-modules/ruoyi-talent/pom.xml`：`parent = org.dromara:ruoyi-modules:${revision}`，依赖全部**不写 version**（由 `ruoyi-common-bom` 统一管理）。
2. `ruoyi-modules/pom.xml:18-25` 的 `<modules>` 加 `<module>ruoyi-talent</module>`。
3. 根 `pom.xml` 的 `<dependencyManagement>` 加 `org.dromara:ruoyi-talent:${revision}`。
4. `ruoyi-admin/pom.xml` 加 `ruoyi-talent` 依赖。
5. **启动类 `DromaraApplication` 不用改**（同 `org.dromara` 根包，`@SpringBootApplication` 自动扫描）。
6. **Mapper 扫描零配置**：`@MapperScan("${mybatis-plus.mapperPackage}")`，`mapperPackage=org.dromara.**.mapper`、`mapperLocations=classpath*:mapper/**/*Mapper.xml`、`typeAliasesPackage=org.dromara.**.domain`（`application.yml:121-125`）。
7. 配置类样板：`GenProperties`（`@Component` + `@ConfigurationProperties(prefix="gen")` + `@PropertySource(classpath:generator.yml, YmlPropertySourceFactory)`）→ 人才库用 `TalentProperties` + `talent.yml`。
8. 代码生成器模板目录是 `ruoyi-modules/ruoyi-gen/src/main/resources/fm/`，后缀 **`.ftl`**（不是 `.fm`）；产出结构含 `domain / domain/vo / domain/bo / mapper / service / service/impl / controller` 与 `resources/mapper/{moduleName}/{Class}Mapper.xml`，前端产出 `vue/api/{module}/{business}/index.ts+types.ts`、`vue/views/{module}/{business}/index.vue`。

## 7. 基线可构建性验证（本地实测）

```powershell
# 环境（不污染系统变量）
. D:\DeepseekHarness\.tools\env.ps1
# 或
cmd /c "D:\DeepseekHarness\.tools\mvn.cmd -DskipTests -Dmaven.test.skip=true -T 1C install"
```

- 结果：**BUILD SUCCESS**（40 个模块全部 SUCCESS，日志 `logs/build-baseline2.log`）。
- **遇到的坑**：`mapstruct-plus` 1.5.1 的注解处理器在静态初始化时写 `$user.home\.msp\incrementMark`，且不会自动创建父目录，在受限沙箱下写入 `C:\Users\hehuo\.msp` 被拒 → `ExceptionInInitializerError: IOException 系统找不到指定的路径`。
- **解决**：构建期把 `user.home` 重定向到工作空间内并预建目录（`.tools\env.ps1` / `mvn.cmd` 中 `MAVEN_OPTS=-Duser.home=D:\DeepseekHarness\.tools\home`，并预建 `home\.msp`）。
- 影响范围：仅本地构建环境，**不改动工程与业务代码**。生产/CI 上 `$user.home` 可写，无需该设置。
