### 两个环境坑与解法（值得记录）

1. **Windows schannel 阻断 HTTPS**：本机 `Invoke-WebRequest` / `curl.exe` 均报 `SEC_E_NO_CREDENTIALS`。解法：`git` 用 `-c http.sslBackend=openssl`；大文件下载改用 Node 自带 OpenSSL 栈（`dl.mjs`）。
2. **mapstruct-plus 导致基线编译失败**：其注解处理器静态初始化时写 `$user.home\.msp\incrementMark` 且不创建父目录，而 `C:\Users\<user>` 在工作空间外、被文件沙箱拒绝写入 → `ExceptionInInitializerError: IOException 系统找不到指定的路径`。解法：构建期把 `user.home` 重定向到 `D:\DeepseekHarness\.tools\home` 并预建 `.msp` 目录。**只影响本地构建，生产/CI 无此问题。**

## 4. 风险登记册

| 风险 | 影响 | 已采取的措施 | 残余风险 |
|---|---|---|---|
| 6.0.0 不兼容升级导致 API 误用 | 大面积返工 | S0 强制事实核对 + 4 份带行号证据的侦察稿 | 编译期可暴露大部分；运行期行为需部署后验证 |
| 区域越权 | 数据泄露（高） | 服务端显式过滤为唯一权威；按 ID 二次校验；验收含 5 条越权用例 | 需部署后跑越权用例实测 |
| 手机号脱敏依赖配置开关 | 密文等同明文 | 已列入上线前必查项 | 需运维执行 |
| 附件下载旁路 | 绕过授权下载简历 | 人才附件不登记 `sys_oss`；下载走服务端流式代理；响应不含对象键/URL | 需确认无人手工把附件写入 `sys_oss` |
| 病毒扫描缺失 | 恶意文件入库 | 状态机 + 回调接口；未接入时置 `CLEAN` 并留痕 | 一期无真实扫描能力 |
| 解析能力涉及个人信息 | 合规风险（高） | 默认关闭；只用虚构样本 | 需业务侧审批 |
| SQL 未在真实 MySQL 执行 | 建表失败 | 结构自检器校验列数/重复行；`bigint(20)`/`datetime` 与框架初始化脚本同风格 | **需在测试库执行一次** |
| 前端 `pnpm build` 未验证 | 交付不可用 | 已要求实际执行 `pnpm build` 并报告结果 | 待执行 |
