# 集团人才库 验收与测试用例（POC 阶段）

> 对应设计文档 §11「验收映射」。每条用例给出**可复现步骤 + 预期结果 + 证据形式**。
> 前置：已执行 `sql/V1__talent_schema.sql`、`sql/V2__talent_menu_role_dict.sql`；已建 6 个角色账号（`talent_admin` / `talent_hr_group` / `talent_hr_sz` / `talent_hr_st` / `talent_viewer` / `talent_auditor`）。
> **所有测试数据必须为虚构数据**（解析能力获批前不得使用真实简历，见设计文档 §13.4）。

## 1. 跨深圳、汕头共享（对应验收重点「跨深圳、汕头共享」）

| 编号 | 用例 | 步骤 | 预期结果 | 证据 |
|---|---|---|---|---|
| A-01 | 深圳 HR 只能看到 SZ + GROUP | 分别用 SZ HR / ST HR 登录，打开人才档案列表，不填任何区域筛选 | SZ HR 结果集只含 `region_code ∈ {SZ, GROUP}`；ST HR 只含 `{ST, GROUP}`；两者 GROUP 记录可见 | 两账号列表截图 + 返回 JSON 的 `regionCode` 字段 |
| A-02 | **前端伪造区域参数无法越权** | SZ HR 调用 `GET /talent/profile/list?regionCode=ST` | 返回空集或仅 SZ+GROUP（**绝不返回 ST 专属记录**） | 接口响应截图 |
| A-03 | **前端伪造 region_code 新增越权** | SZ HR 用 `POST /talent/profile` 提交 `regionCode=ST` | 返回失败：无权在该区域新增/编辑 | 接口响应 + 无新记录 |
| A-04 | 集团 HR 全区域可见 | 集团 HR 登录查看列表 | 可见 GROUP/SZ/ST 全部记录 | 列表截图 |
| A-05 | 汕头 HR 不可修改深圳人才 | ST HR 调 `PUT /talent/profile`，`talentId` 指向 SZ 记录 | 失败：无权访问该人才档案（先做单条二次校验） | 接口响应 |

## 2. 一人上传多人查阅（对应「一人上传多人查阅」）

| 编号 | 用例 | 步骤 | 预期结果 | 证据 |
|---|---|---|---|---|
| B-01 | 上传成功且不可直接下载前扫描完成 | 深圳 HR 上传 `test-resume.pdf`（≤25MB） | 上传成功；附件列表出现 v1 且 `isCurrent=1`；`scanStatus` 为 `CLEAN`（未启扫描时）或 `PENDING` | 附件列表截图 |
| B-02 | 版本推进 | 同一人才同一类型再传一份 | 新附件 `version=2, isCurrent=1`；旧附件 `isCurrent=0` 且**原文件仍可下载**；旧文件未被物理删除 | 版本列表 + 两次下载成功 |
| B-03 | 跨区域查阅（GROUP 共享） | 深圳 HR 上传到 GROUP 档案 → 汕头 HR 登录查看并下载 | 汕头 HR 可见且可下载 | 两账号截图 |
| B-04 | **越权下载被拒** | ST HR 直接调用 `GET /talent/attachment/download/{attachmentId}`，该附件属于 SZ 专属档案 | 失败：无权访问；`tl_sensitive_audit` 记录 `action=DOWNLOAD, result=1` | 接口响应 + 审计表查询 |
| B-05 | **枚举 attachmentId 无法遍历** | 用普通查阅者账号连续尝试 5 个不存在的/未授权的 attachmentId | 全部失败，且每次失败都产生审计记录 | 接口响应 + 审计条数 |
| B-06 | 未通过扫描禁止下载 | 手工把 `scan_status` 改为 `INFECTED`/`PENDING`，再下载 | 失败：附件未通过安全扫描，禁止下载 | 接口响应 + 审计 |
| B-07 | 扩展名白名单 | 上传 `.exe` / `.zip` | 失败：文件类型不允许 | 接口响应 |
| B-08 | 大小上限 | 上传 30MB 文件 | 失败：文件超过大小限制（Nginx / Spring / OSS 三层一致） | 接口响应 |

| 编号 | 用例 | 预期结果 | 证据 |

| G-04 | 单条授权有效期 | 给查看者授予 `VIEW`，`endTime` 设为 1 分钟后 | 授权期内可见；过期后不可见 |
| G-05 | 授权撤销 | 撤销授权后再访问 | 立即不可见 |
| G-06 | 超级管理员不默认绕过 | 用超管访问完整简历/下载 | 仍产生审计事件 |
| G-07 | 日志排敏 | 全文检索应用日志（`logs/`） | 无完整手机号、无 Token、无简历正文、无对象存储 URL |

| G-09 | 审计不被业务回滚带走 | 构造"下载成功但后续步骤失败"的场景 | 审计记录仍存在（`REQUIRES_NEW` 生效） |
| G-10 | 菜单/按钮权限生效 | 无 `talent:profile:add` 权限的账号访问新增接口 | 403；前端按钮不显示 |

## 9. 必须在验收前确认的配置项（**易漏**）

| # | 配置 | 位置 | 不配置的后果 |
|---|---|---|---|
| 1 | `mybatis-encryptor.enable: true` + AES 密钥 | `application.yml` | 手机号密文字段等同明文，**不满足脱敏存储要求** |
| 2 | `talent.phone-hash-salt` 使用真实密钥（非默认值） | `talent.yml` | 哈希可被彩虹表/跨库比对 |
| 3 | `sys_oss_config.access_policy = '0'` | 数据库 | 简历桶可能公读 |
| 4 | `talent.parse-enabled: false`（获批前） | `talent.yml` | 违反个人信息处理审批前提 |
| 5 | `talent.virus-scan-enabled` 与实际扫描服务一致 | `talent.yml` | 状态语义与事实不符 |
| 6 | Nginx / Spring(`spring.servlet.multipart`) / OSS 三层 25MB 限制一致 | 配置 | 出现"前端允许、后端拒绝"或反向情况 |
