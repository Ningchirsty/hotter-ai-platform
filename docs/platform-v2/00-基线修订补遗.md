## 一、§1.1「已实现事实」核对结果：12/12 准确

设计文档 §1.1 的 12 条经逐条核对**全部成立**，包括四个看文档抄不到的细节：

| 被核对的关键结论 | 依据（源码位置） |
|---|---|
| 没有"新建 Agent/Skill"的业务接口 | `IAigAgentRegistryService` 仅 5 个方法：`advanceRelease`/`missingGates`/`wasEverStable`/`scanStoredManifest`/`addBinding` |
| `provider_capability` 仅声明、不参与路由 | 全仓库仅"写入/查询/展示"三处引用，**无任何路由或调用代码读取** |
| Agent 版本 `allow_external` 不参与路由 | 路由只读 `aig_route_policy.allow_external`（`AigRouteServiceImpl:196`）与 `STRICT` 硬禁令（:201-209） |
| `SANDBOX_RUN` / `HUMAN_APPROVAL` **无独立凭证校验** | 只有 `assertManifestScanEvidence` / `assertGoldenCaseEvidence` / `assertCanaryEvidence` 三个断言（`AigAgentRegistryServiceImpl:301/333/360`），另两者**没有对应断言** |
| 受限通道绑定**只对 Agent 版本**校验 | `assertBindingExistsIfLimitedChannel` 内 `type != AGENT_VERSION` 直接返回（:406） |
| 灰度证据必须携 `agent_version_id` | `AigCanaryEvidence` 只统计审计中归属该版本的行 |

**结论**：设计文档的基线可信，**可以据此冻结 P0-001 的基线部分**。

## 二、§1 的**两处遗漏**（都在它自己引用的 `6503058` 里）

### 2.1 `aig_task.execution_mode`（已上线）

| 项 | 事实 |
|---|---|
| 取值 | `PLATFORM`（默认）=平台执行，走统一调用入口；`EXTERNAL`=业务域执行，**平台只登记与展示、不执行也不扫描** |
| 关键语义 | 调度器的**重试/超时清扫只碰 `PLATFORM`** |
| 依据 | `aig_task.execution_mode`（NOT NULL default `PLATFORM`）；迁移 `script/sql/aig_task_execution_mode.sql` |

**为什么必须补进基线**：设计文档 §10「Workflow & Task Orchestration」的第 1 条就是"外层业务 Workflow / 内层 Agent Workflow / 计算任务"的分层，而**平台已经实现了"业务域执行的任务平台不碰"这条边界**。不补进来，阶段 1 会重复设计。

| 项 | 事实 |
|---|---|
| 字段 | `dp_generation.aig_task_id`；创作域出图时登记一条 `aig_task`（执行方=业务域 EXTERNAL），并做状态回写 |
| 依据 | 迁移 `script/sql/dp_generation_aig_task_id.sql`；`AigTaskEvent` 事件账本 |

## 三、§1.2 六项 `[待核验]`：结论

> 这六项设计文档明确说"不能以附件替代源码"。以下结论均来自源码/生产实测。

### 3.1 `aig_task` 的状态、队列、幂等、checkpoint、取消、重试 —— **大部分已具备**

| 能力 | 现状 | 依据 |
|---|---|---|
| 状态机 | **14 态**：`DRAFT`/`POLICY_CHECKING`/`QUEUED`/`DISPATCHED`/`RUNNING`/`SUCCEEDED`/`FAILED`/`RETRY_WAIT`/`CANCEL_REQUESTED`/`CANCELLED`/`NEED_HUMAN`/`REVIEW_PENDING`/`APPROVED`/`REJECTED`（后三者终态） | `AigTaskStateMachine` |
| 幂等 | 唯一键 `(project_type, create_by, idempotency_key)`；命中即返回既有任务 | `AigTaskServiceImpl:250` |
| 并发 | 乐观锁 `expectedVersion`（compare-and-set） | `transition(taskId, expectedVersion, …)` |
| 重试 | `attempt_no` / `max_attempt`（默认 3）+ `RETRY_WAIT` | `AigTaskServiceImpl:72,281-283,501-521` |
| 取消 | `CANCEL_REQUESTED → CANCELLED` | `AigTaskStateMachine` |
| 事件账本 | `aig_task_event(task_id, sequence, event_type, from_status, to_status, attempt_no, payload_json, trace_id)` | `AigTaskEvent` |
| **检查点** | **没有**（只有输入快照 `aig_task_snapshot`） | — |
| 队列 | **DB 当队列 + 定时清扫**：`AigTaskSchedulerImpl.sweep()` → `sweepRetryWait` + `sweepTimeout`（对外 `POST /aigov/task/scheduler/sweep`） | — |

**对方案的影响（重要）**：设计文档 §13.2 的 `aig_execution` / `aig_execution_event` 与现有 `aig_task` / `aig_task_event` **职责重合约 90% / 95%**。
→ 采纳建议：**扩展 `aig_task`，只新增 `aig_task_step` 与 `aig_task_checkpoint`**。详见 §四。

### 3.2 Package 扫描器：**没有压缩包安全检查——因为现在根本不解析压缩包**

| 项 | 事实 |
|---|---|
| 上传物 | 只被算一次 SHA-256 与 Manifest 声明的 `checksum` 比对；**包体不入库、不解压、不执行** |
| 校验器性质 | `AigPackageManifestValidator` 是**纯文本字段判定**（白名单 + 五类拒绝规则），并明确声明"平台不执行 Manifest 里的任何东西" |
| zip-slip / 压缩炸弹 / 符号链接 / 恶意依赖 / 许可证 / 签名 | **零实现** |
| 现有"扫描"结论 | `scan_result` 指的是**Manifest 校验**结论，不是文件安全扫描 |

**对方案的影响（高）**：V2 一旦真的解压 ZIP、落 `scripts/`、跑容器，**这是一条全新的攻击面**。
**不得在任何材料里宣称"现有扫描器已覆盖"**。设计文档 §16.3 列的全部要求都属于**新增**，且 `P1-003 Script Sandbox Worker` **依赖它**，必须排在前面。

### 3.3 模型网关能否跨进程/跨语言调用：**能调，但没有机器身份**

| 项 | 事实 |
|---|---|
| 入口 | `POST /aigov/invoke/{capabilityCode}`，功能完整（路由 + 配额 + 调用审批 + 审计） |
| 鉴权 | **Sa-Token 会话**（给人用的登录态），未见服务令牌 / mTLS / 机器身份 |
| 费用聚合 | 只有逐次审计的 `cost`（多数为 NULL——供应商不回执，平台已明确"为空=未知≠免费"） |

**对方案的影响（高）**：Python/外部 Agent 要复用统一模型治理，**必须先补一层服务身份与配额归属**。
否则只有两条路：给它一个"人"的会话（不可接受）或绕过治理（更不可接受）。
→ 建议作为**独立任务**提到阶段 1 之前（见 ADR-002 与执行计划新增项）。

### 3.4 运行环境版本与拓扑

| 组件 | 实测 |
|---|---|
| MySQL | 8.0.36（容器 `ai-video-poc-mysql-1`，库 `ai_video_poc`） |
| Redis | 7.4-alpine（`ai-video-poc-redis-1`） |
| 对象存储 | MinIO（`ai-video-poc-minio-1`，9000/9001） |
| 后端 | 单容器 `ai-video-poc-backend-1`（宿主 18082 → 容器 8080） |
| 前端 | `ruoyi-web`（nginx，:80）+ `pm.hottter.cn` |
| 推理 | GPU 侧 ComfyUI（`192.168.2.223:8188`）；`creative-renderer`；snail-ai 独立容器 |
| **消息队列** | **没有**（`application.yml` 无 rocketmq / rabbitmq / kafka / outbox 配置） |

**对方案的影响（高）**：设计文档 §3.3「如无 MQ 可先做数据库 Outbox + Polling Worker」——**现状连 Outbox 也没有**，现有模式就是 `aig_task` + `sweep()`。
→ 要么补 MQ（需评估运维成本与 RTO/RPO），要么按 sweep 模式设计，并**重新对齐"事件写入后 5 秒内可见"这个目标**（sweep 周期决定下限）。

### 3.5 组织/数据权限 ID 与 `create_dept` —— **需 DBA/业务确认，本文不能替它定**

| 已观察 | 说明 |
|---|---|
| `create_dept` 存的是**部门 ID**（如 `1761000000000000103` 研发部） | 与"集团/子公司/品牌/项目"**不是同一套树** |
| 品牌/项目是业务域自己的概念 | 品牌/项目主数据在业务域表中，不在治理层 |

**对方案的影响**：设计文档 §16.5 建议"建立显式 `org_scope`（GROUP/SUBSIDIARY/BRAND/PROJECT）并关联现有组织主数据"——**方向正确**，但**必须先确认品牌/项目主数据在哪张表**，否则会造出第二套组织树（文档自己也警告了这一点）。
→ 列为**待冻项 F-05**（见 `03-冻结清单-12项.md`）。

### 3.6 是否已有独立审批/制品/限额/工具注册组件

| 组件 | 现状 | 结论 |
|---|---|---|
| 审批 | **有**：`aig_call_approval`（人 × 能力 × 数据等级、带有效期、CAS 并发、申请人不得自审、驳回必填原因） | **复用，不重造** |

| 工具注册 | **没有** | 真新增 |

## 四、表设计结论：`aig_execution*` 应收敛为 `aig_task*` 的扩展

| 设计文档提议 | 现有对应物 | 覆盖度 | 结论 |
|---|---|---|---|
| `aig_execution` | `aig_task`（status / route_snapshot / idempotency_key / cost_amount / latency_ms / error_code / version 乐观锁 / policy_result+policy_reason / provider_code+provider_job_id / execution_mode） | ~90% | **扩展，不新建** |
| `aig_execution_event` | `aig_task_event`（task_id, sequence, event_type, from_status, to_status, attempt_no, payload_json, trace_id） | ~95% | **复用** |
| `aig_execution_step` | 部分（`aig_task_result` + `aig_task_event`），缺"逐节点"粒度 | ~40% | **新增 `aig_task_step`** |
| `aig_execution_checkpoint` | 无 | 0% | **新增 `aig_task_checkpoint`** |
| `aig_artifact*` | **`aig_task_artifact` 已落地（2026-10-09）**；制品版本/血缘类表仍无 | 账本部分完成 | 新增（首张表已完成） |
| `aig_runtime_def`/`_deploy`/`aig_version_runtime_binding` | 无 | 0% | 新增 |
| `aig_tool_def`/`_version`/`_grant` | 无 | 0% | 新增 |
| `aig_workflow_*` / `aig_scenario_*` | 无 | 0% | 新增 |
| `aig_policy_decision_log` | 无 | 0% | **新增（M-005 的举证依赖它）** |
| `aig_runtime_evidence` | 无 | 0% | **新增（补两道弱门槛的依赖它）** |

**净结果**：新增表从设计文档的"17 组"收敛为 **约 11 组新增 + 3 组扩展（`aig_task`/`aig_task_event`/可选 `aig_task_result`）+ 2 组复用（`aig_call_approval`/`aig_user_quota`）**，
且**执行事实源保持唯一**（这是 CANARY 灰度证据与发布门槛能继续工作的前提）。
