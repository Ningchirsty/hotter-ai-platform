# 06 沙箱产物进平台 —— 设计草案（**待确认后再写代码**）

> 状态：草案。**没有开始实现**。本文只回答"怎么做、代价是什么、哪些点必须由人定"。
> 前置阅读：`01-ADR-决定记录.md` 的 ADR-015（沙箱执行与证据链，含「已知边界」一表）。

## 1. 要解决的问题

现在一次沙箱作业的产物是**宿主机的文件**：worker 归档到 `/var/lib/hotter-sandbox/archive/<jobId>/`，
平台侧只有账本 `aig_sandbox_run` 里 `result.json` 原文所带的**清单**（路径/字节数/sha256）。
运维可以用 `sandbox-archive.sh export <jobId>` 打出可交付的包，**但平台里看不到、取不到产物本体**。

目标：**让产物在平台里可见、可取，并且取的过程可审计**。

## 2. 边界（先说清不做什么）

| 不做 | 为什么 |
|---|---|
| 平台自己去读宿主归档目录 | 平台后端**没有也不该有**宿主文件系统访问权（ADR-015 的边界：后端无 docker CLI/socket）。共享挂载会把"运行不可信代码"的能力变相给平台 |
| 解析/预览/再加工产物内容 | 产物是**不可信内容**。先只做"存下来、按权限取走"，别急着渲染 |
| 把产物当可信内容内联展示 | 见 §5 安全面第 1 条（XSS/CSRF 的现成载体） |
| 平台主动外发产物 | 出网策略属 F-09（未冻） |

## 3. 三个候选通道（我给推荐）

| 方案 | 做法 | 判断 |
|---|---|---|
| **A. 平台接收（推荐）** | 运维用已有的 `sandbox-archive.sh export <jobId>` 出包，再通过**新上传接口**把文件交给平台；服务端按账本里声明的 sha256 **逐个校验**后存对象存储 | 不改后端容器挂载、不开服务令牌开关，与已接受的"管理员人工登记"（ADR-015 第三切片）同一套路：**先人工、后自动** |
| B. worker 直传 | worker 用服务身份把产物推给平台 | 需要**服务令牌开关打开**（当前关闭）+ 宿主侧凭据 + worker 常驻；通道 A 下不优先 |
| C. 平台读宿主目录 | 共享挂载 / NFS | **否**：破坏边界（见 §2） |

## 4. 数据与接口（方案 A 的具体形状）

### 4.1 表

我倾向**新表** `aig_sandbox_artifact`（追加型账本，同 `aig_sandbox_run` 口径：无 `del_flag`／无 `update_*`）：

| 列 | 说明 |
|---|---|
| `artifact_id` | 主键 |
| `sandbox_run_id` | 指向 `aig_sandbox_run`（**不是** task：沙箱作业不是任务） |
| `path` | 产物相对路径（与 `result.json` 里声明的一致） |
| `bytes` / `sha256` | **服务端实算**并与账本声明比对后写入 |
| `object_key` | 对象存储键，**由服务端生成**（`sandbox/<runId>/<sha256>`），绝不用上传方的 path 拼 |
| `content_type` | 记录上传方声明的类型（**只记录，不用于回显**） |
| `uploaded_by` / `create_time` | 谁在什么时候登记的 |

唯一键 `(sandbox_run_id, path)`：同一产物只能登记一次（与 `job_id` 唯一同理——重复登记会让"存了几份"变成假账）。

### 4.2 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/aigov/sandbox/run/{runId}/artifact` | `aig:sandbox:record` | multipart：`path` + 文件。**服务端校验**：路径在账本声明清单内、字节数一致、**sha256 一致**；不符即拒绝并说明差在哪 |
| GET | `/aigov/sandbox/run/{runId}/artifacts` | `aig:sandbox:list` | 元数据列表（path/bytes/sha256/是否已入库） |
| GET | `/aigov/sandbox/run/{runId}/artifact?path=…` | `aig:sandbox:list` | 下载（见 §5 的响应头硬要求） |

**只信账本、不信上传方**：校验基准是 `result.json` 里声明的 `path/bytes/sha256`——那是登记门槛时就已经存证的东西。
上传方**无法**塞进一个"清单里没有"的文件，也**无法**替换掉清单里文件的内容。

## 5. 安全面（本节是这份设计最该被审的部分）

1. **永不内联渲染**：产物由不可信代码在沙箱里产生，可以是 HTML/SVG/JS。下载响应必须
   `Content-Type: application/octet-stream`（**不回显上传方的 content_type**）、
   `Content-Disposition: attachment; filename="…"`、`X-Content-Type-Options: nosniff`。
   否则就是"在平台域下执行外部代码"的一条现成通道。
2. **路径不许穿越**：`path` 只接受相对路径，拒绝绝对路径、`..`、反斜杠；对象键由服务端按
   `sha256` 生成，不参与拼接。
3. **限额**：单文件上限（建议 512MB，与 scratch 1G 上限相称）、每 run 文件数上限、每 run 总量上限。
4. **存储隔离**：对象存储用独立前缀；**不生成公开 URL**；下载一律走平台鉴权。
5. **审计**：谁下载了哪个产物要留痕（接现有操作日志或新增一行账本）。
6. **不因为"已入库"就放松登记校验**：门槛证据仍只看 `aig_sandbox_run`，产物入库与门槛无关
   （两者失败方式不同，别混）。

## 6. 必须由人定的四件事（**确认后我再动代码**）

1. **表**：新开 `aig_sandbox_artifact`（我推荐）还是复用 `aig_task_artifact`？
   复用的前提是"沙箱作业将来都会挂在某个 task 下"——如果是，复用更省；如果不是，`task_id` 会长期为空。
2. **上传粒度**：**逐文件**（我推荐：校验粒度细、失败可重试）还是整包 tar.gz（服务端解包校验）？
3. **保留策略**：平台侧留多久、多大（对象存储不是无限的）；超限删最旧还是拒绝新上传？
4. **是否允许非附件下载**：我建议**永远不允许**（见 §5-1）。若业务确实需要图片预览，需要单独评审
   （独立域/独立桶 + 严格 CSP），不要在这一版顺手放开。

## 7. 实施顺序（确认后照此做，每步都要有验证）

1. SQL：建表（幂等脚本 + `sql-order.txt`）+ 发布检查加"表/列存在"断言；
2. 后端：实体/Mapper/服务（校验 + 对象存储）/Controller + **单测**（sha256 不符拒绝、路径越界拒绝、
   超限拒绝、重复登记拒绝、下载响应头断言）；
3. 前端：证据块里列出产物并提供下载（按钮按 `aig:sandbox:list` 授权）；
4. 发布：SQL → 后端镜像 → 前端镜像（**当前宿主机拉不动镜像，需要走 LAN 搬运**，见运行手册 §4.6）；
5. 生产验证：真跑一次作业 → 导出 → 上传 → 列表 → 下载并核对 sha256 → 清理。

## 8. 现在就能用的一半

平台侧还没做之前，运维侧已经不缺工具：
`/opt/hotter-sandbox/sandbox-archive.sh export <jobId> [--out FILE]`
——先 `verify` 自检（篡改过的归档拒绝导出），再打成 tar.gz 并打印包 sha256/大小/条目数。
生产实测见 ADR-015 补偿记录（R115，0 失败）。
